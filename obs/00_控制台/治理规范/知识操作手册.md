# Ingest、Query、Lint、Promote 操作手册

> [!warning]
> 本页是只读派生视图；如与 canonical 来源不一致，以 `D:\666\AI_Global_Assistant\knowledge_operations_rules.md` 为准。

| 操作 | 最小产物 | 不允许自动完成 |
|---|---|---|
| Ingest | source、单源 evidence、ΔK route、delta_operation、局部 lint | 批量语义写入、自动升格 |
| Query | canonical 优先的回答、必要时回查 primary | 把回答直接写成 approved/L2 |
| Lint | 断链、重复、证据、版本、泄漏和状态报告 | 自动裁决冲突或重写语义 |
| Promote | 完整来源、范围、验证与批准记录 | L1→L2、L2→L3 自动批准 |

`ΔK route` 只使用：`no-change / project-only / obs-candidate / global-config-candidate`。有语义增量时另记 `delta_operation`：`create / update / contradict / supersede / question`；`no-change` 不是变更动作，也不生成事件。

## 写入边界

明确授权的单源任务可以新建 L0/L1 和机械更新索引；修改已有正文语义、批量写入、合并、重命名、删除、升格和跨项目发布必须先审 diff 或变更清单。

## 项目任务收尾四路由

任务先判定 `closeout_outcome`，再对实际形成的知识增量执行路由；知识路由完成本身不代表任务已完成。

| 路由 | 处理 |
|---|---|
| `no-change` | 不入库；可追加一条简短日志 |
| `project-only` | 只更新对应项目 KB，不复制到 Obsidian |
| `obs-candidate` | 自动生成来源指针、查重结果和 L0/L1 草案；获得目标位置写入授权后进入 Obsidian 审核 |
| `global-config-candidate` | 交给 AI_Global_Assistant 的配置候选流程，不作为工程知识写入本 Vault |

用户无需手工复制 Markdown、填写 YAML 或维护双链。默认由 Codex 完成发现、分类、抽象草案和 lint；得到相应写入授权后机械维护候选、索引和链接。项目事实确认、脱敏、升格、跨项目放行、冲突裁决和删除保留人工批准。

## 失效操作顺序

`发现触发器 → pending_review + 健康标记 → 下游影响分析 → 人工裁决 → 更新状态与替代链接 → index/log/Base 更新 → 查询回归`

在恢复机制未验证前，不执行批量物理清理。
