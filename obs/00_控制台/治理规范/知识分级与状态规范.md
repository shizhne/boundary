## 快速规则

- 成熟度：L0 线索、L1 候选、L2 人工确认、L3 按风险完成验证。
- 审核状态：`inbox / candidate / needs_redaction / pending_review / approved / rejected / deprecated`。
- 范围：`personal / project:V500E / project:volant_XJ / cross-project / global`。
- 敏感级别：`public / internal / project_confidential / restricted`。
- 记录角色：`canonical / pointer / derived_view`。
- 健康标记仅使用：`stale / conflicted / superseded`。

## 默认工程准入

只有 `record_role=canonical`、`maturity=L2/L3`、`review_status=approved`、范围与敏感级别匹配、无健康阻断标记，且 `review_due` 已填写并尚未到期的条目，才能作为默认工程结论。

高风险控制律、接口、参数、试飞结论、安全约束和模型集成知识升 L3 时，必须同时有可复现产物、明确版本/工况和责任人确认。

能够进入默认工程检索的 L2/L3 页面必须填写 `last_verified`、`review_owner` 和日期格式的 `review_due`：高风险 90 天、中风险 180 天、低风险 365 天；来源、项目基线或可信冲突事件可提前触发复核。

## 失效与隔离

- 来源变化或复核到期：`review_status=pending_review` 并标记 `stale`。
- 出现高可信冲突：`review_status=pending_review` 并标记 `conflicted`。
- 被新条目替代：旧条目置 `review_status=deprecated`、添加 `superseded`，并填写 `superseded_by`。
- 被推翻但暂无替代：置 `deprecated`，填写 `status_reason / invalidated_at / invalidated_by / decision_ref`。
- `rejected` 只用于从未生效的候选，不能替代 `deprecated`。

先让失效条目退出默认检索，再执行修订、替代或归档；不得静默覆盖或自动删除。
