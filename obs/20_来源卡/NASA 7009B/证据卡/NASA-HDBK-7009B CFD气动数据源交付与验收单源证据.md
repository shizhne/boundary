# NASA-HDBK-7009B CFD气动数据源交付与验收单源证据

> [!warning]
> 本页只对应 NASA-HDBK-7009B 这一份 primary 来源。HDBK 提供实施指导而非独立强制条款；其中示例和解释不能未经项目采纳就写成合同 `shall`。

## 一句话结论

NASA-HDBK-7009B 把 7009B 的可信度框架落实为 Data Pedigree、问题/精度/域定义、数值误差评估、校准与留出验证、比较前冻结准则、独立评审、发布和变更证据，可直接支持 CFD 数据需求书设计，但没有给出统一 CFD 阈值或文件格式。

## 关键假设和适用边界

- **来源明确事实**：模型开发、嵌入和验证时使用的数据属于 Data Pedigree；运行时数据属于 Input Pedigree。见 §4.5.1（PDF p.34）和 §5.1.1.5（p.52）。
- **来源明确事实**：高保真气动数据库经常综合风洞和 CFD 数据；这是一种实施背景，不是所有项目必须双源的强制要求。见 §5.1.1.5（p.52）。
- **作者推导**：计算代理模型继承源计算模型的假设和限制，同时增加自身的拟合/降阶限制。见 §4.5.2（PDF pp.35–36）。
- **合理推测**：供应方提供的 CFD 气动表或场数据，应按开发期 Data Pedigree 主线验收；只有被下游模型运行时读取的数据，才额外进入 Input Pedigree 评估。
- **适用边界**：HDBK 用于解释证据如何形成，不能替代项目合同、CFD 学科专标和项目验收阈值。

## 核心问题

如何把预定用途、数据谱系、数值验证、物理验证、不确定度、独立性和发布控制组织成一个可审计而不过度索取全部中间过程的 CFD 数据证据包？

## 方法输入、输出与步骤

### 输入

- 用户问题或 SRQs、预测量、应用域和验证域。
- 目标精度、精密度、不确定度预算、禁用和谨慎使用情况。
- CFD 计算数据、求解器/网格/数值设置证据和后处理链。
- 风洞、试验或其他经验参照及其采集、处理和不确定度证据。
- 发布基线、配置变更和评审角色。

### 输出

- Data Pedigree 与证据索引。
- 代码/解验证及数值误差界定结果。
- 校准记录、独立留出验证结果、验证域和未验证区域。
- 偏差、精度、精密度、敏感性和不确定度说明。
- 允许用途、限制/placard、发布版本和变更触发重验规则。

### 实施链

1. 定义模型要回答的问题、输出、精度、域和禁用场景。
2. 规定代码质量、数值误差、网格/时间采样和验证设施/指标策略。
3. 统一单位、坐标系和转换约定。
4. 在经验确认前完成代码/解验证，并保存测试域与误差估计。
5. 检查经验参照的来源、采集、处理、兼容性和不确定度。
6. 将校准数据与留出验证数据分离，在看到比较结果前冻结准则。
7. 带着双方不确定度比较结果，记录验证域、偏差和未通过项。
8. 建立发布基线、限制、可追溯变更和随版本提供的 V&V 结果。

## 关键公式或算法

- **文中未说明**：没有统一的 CFD 验收公式、网格收敛公式、系数误差限或文件 Schema。
- §5.5.3.2.1 及 Figs. 10–11（PDF pp.82–84）把不确定区间重叠作为 quick-look，并建议用统计检验获得更客观判断；手册没有指定唯一统计检验。
- 文中出现的“99% confidence / error less than 1%”属于说明性示例，不能转写为普遍要求。

## 结果与验证证据

- §4.4，PDF p.33：要求保存活动及结果证据，但不必为每项要求新建独立文档；引用现有受控证据可以满足文档要求。
- §4.5.1，PDF p.34：定义数据 pedigree/provenance 的 lineage、traceability 和 quality 角色，并区分 Data 与 Input Pedigree。
- §4.5.2，PDF pp.35–36：计算代理继承源模型限制并增加自身限制。
- §5.1.1.2，PDF pp.47–49：预定用途应说明模型做什么、输出、限制、应用、环境、场景和避免使用的情况。
- §5.1.1.5，PDF p.52：风洞和 CFD 可共同用于高保真气动数据库；开发/嵌入/验证数据进入 Data Pedigree。
- §5.2.1.1，PDF p.56：模型团队与地面、飞行或运行数据采集团队协作定义验证参照需求。
- §5.2.1.3.1，PDF pp.59–60：定义问题、预测量、精度、应用/验证域、客户问题、代码/QA、数值误差、网格能力、验证设施/指标及输入不确定度传播。
- §5.2.1.3.4，PDF p.62：规定单位、坐标系和转换约定。
- §5.5.1 与 Fig. 6，PDF pp.72–74：Verification 应先于 empirical Validation，模型和经验数据的不确定度链都要检查。
- §5.5.2，PDF pp.75–77：识别、量化或界定重要数值误差；改变容差、空间/时间采样检查稳定性；收敛不能证明准确，生产设置差异进入 UQ。
- §5.5.3 与 Fig. 7、Fig. 8，PDF pp.77–81：定义 Validation Domain，区分 calibration/correlation；只用部分数据调参，保留其余数据验证调参结果。
- §5.5.3.2.1，Figs. 10–11，PDF pp.82–84：比较前确定接受准则与允许不确定度，区间重叠只作快速检查。
- §5.5.5，PDF pp.87–89：发布时建立基线、文档、允许用途、能力评估和可追溯变更，并随发布保留 V&V 程序和结果。
- §5.6.1.2–§5.6.1.3，PDF pp.91–95：Use Assessment 比较用途、域、假设、V&V 限制、输出精度/UQ和输入来源/质量/数量/形式；来自另一模型的数据可信度受源模型限制。
- Appendix B，PDF p.141：需求可以协同，但实际数据/结果宜在双方分别完成验证前保持隔离，再进行比较。
- Appendix D，Table 24（PDF pp.151–153）、Table 26（p.154）、Tables 27–28（pp.155–157）：Data Pedigree、Verification、Validation 和 Technical Review 的实施解释。

## 工程价值与不可直接采用部分

### 可直接借鉴为实施指南

- 用“证据指针 + 受控留存”替代为每项要求重新生产一份文档。
- 先定义问题、预测量、域、精度和禁用场景，再要求供应方组织数据。
- 将代码验证、数据集级解验证、参照质量和经验确认分开审查。
- 校准集、留出集、比较前冻结准则和独立比较共同降低确认偏差。
- 把发布版本、允许用途、限制及变更理由作为交付物的一部分。

### 不可直接采用

- HDBK 的解释不能未经采纳直接改写为合同强制条款。
- 区间重叠、置信度示例和 capability level 不能代替项目量化准则。
- 不能以“来自另一计算模型的数据可信度受源模型限制”推出一个固定的数学上限。
- 不能把 Data Pedigree 与运行时 Input Pedigree 混用。

## 可复现性

- 最小复查需要访问：求解器及物理模型版本、网格族/采样方案、迭代与收敛证据、生产设置、后处理链、参照数据及不确定度、校准和留出记录。
- 供应方若只交最终系数表而不保留上述证据，无法复核数值误差、偏差来源或发布变更影响。
- HDBK 没有提供机器可执行 Schema；要形成可复现交付，仍需项目定义 manifest、字段字典、抽查复算和验收脚本。

## 文中未说明

- CFD 气动力/力矩数据的固定字段、文件格式、参考几何模板和质量标记 Schema。
- 网格规模、湍流/转捩模型、壁面处理、边界条件和收敛阈值的统一选择。
- 每个气动系数的允许偏差、置信区间或误差预算数值。
- 独立验证所需的组织隔离程度、抽样比例、复算数量和签署格式。
- 面向下游拟合的覆盖度、平滑性、局部不连续、插值/外推和留出重构验收指标。
