# VE25SP 模型设计说明迭代升级方案

> 日期：2026-10-14。状态：供审阅的修订方案。本轮已保存现有正文，未实施正文迭代。以下章节安排及纳入建议是本轮核查后的编排判断，尚不作为已批准的设计变更。

## 1 迭代目标与取舍依据

建议保留“有效性处理与来源选择”“一致性监测与数据表决”两条主线，补充当前模型中已确认、但正文尚未解释的数值计算和指令形成方法；系统就绪判定归入现有设备状态章节。已有算法的新增应用集中补充，未确认实现归属的需求另行登记。

当前说明的定位是：**解释 SP 当前数据处理算法的实现设计，帮助读者理解数据如何被判断、选用、转换，以及处理结果如何形成和传递。** 它是理解与维护用的设计草稿，尚不是受控设计基线。需求用于发现应核查的处理内容；当前模型、库、字典及实际调用关系用于确认实现事实。不能仅因需求中存在一项处理，就将其写成当前模型已经执行的算法。

本次扩充应回答“为什么需要该项处理、采用什么判据、状态如何更新、结果如何形成”，而不将文档改为需求逐条复述、模块功能清单、完整接口字典或控制律设计说明。物理量计算及操纵指令生成属于 SP 数据处理，但不展开下游控制律如何使用这些结果。

按以下原则决定说明深度：

- **新增算法说明**：当前引用链中存在，且含有尚未解释的数值计算、事件判定或状态更新机制。提取共性规则，再列应用差异。
- **补充已有算法的应用**：判据或历史处理与正文已有方法相同，仅输入资格、参数、输出位置或无效处理不同。补入原章节，不重复展开共同逻辑。
- **记录需求与实现差异**：双方都有明确证据，但规则、公式或接口不同。分别写清双方行为及待确认依据，不把需求当作当前实现的修订命令。
- **暂缓纳入当前设计正文**：需求存在，但尚未定位当前活动实现。保留需求条目和确认任务；确认实际调用、输入归属及适用构型后再决定是否补写。

**无一致通道时的表决规则对照**

以下统一假设三路 `isSynced` 均为 `false`。“输入有效”指该路输入的 `valid=true`，它与是否被标记为一致是两个不同条件。

空速 Voter 保留按一致状态选择通道和按唯一有效输入选择通道两条支路；没有有效且一致通道时，是否采用后者由 `SpCPT.CASVoterType` 决定。当前磁盘字典保存值为 `int32(2)`，下表空速一行按这一配置说明；它不表示模型中不存在另一条支路，也不证明当前 MATLAB 会话的未保存参数或实际运行值同为 2。

| 对照对象 | 在上述条件下如何处理 |
|---|---|
| 需求 232/C122、233/C123 | 先从上一拍参与计算、且本拍仍有效的通道中，按通道 1、2、3 的顺序选一路；若没有，再从本拍有效的通道中按 1、2、3 的顺序选一路。因此，只要还有一路输入有效，就能选出通道并输出有效；三路均无效时才没有通道参与、输出无效。 |
| 当前 ADAHRU 空速表决及 FTADC／ADAHRU 混合空速表决，按磁盘保存配置 `CASVoterType=2` | 参数为 2 时，不采用任何输入通道的本拍数值，保持上一拍表决数值，并输出 `valid=false`。即使仍有输入通道的 `valid=true`，也不改变这一处理。 |
| 当前 VDT／GPIO 操纵输入表决 | 三路输入中恰好只有一路 `valid=true` 时，即使该路 `isSynced=false`，仍采用该路本拍数值并输出 `valid=true`；若三路均无效，或有两路、三路输入有效，则不采用新的输入数值，保持上一拍表决数值并输出 `valid=false`。 |

若空速 Voter 的 `CASVoterType` 不等于 2，则在没有有效且一致通道时进入另一条支路：恰好一路输入有效时，采用该路本拍数值并输出有效；有两路或三路有效时仍不选择通道。因此，不能将参数为 2 时的行为写成空速 Voter 在所有配置下都执行的规则。两种配置均未实现需求所述的历史参与优先及按通道顺序选择。

这项差异在于：没有一致通道时，是否继续使用仍然有效的输入，以及按什么条件选择该输入。应直接说明这些条件、配置和动作，不能只用“严格一致”“唯一有效输入单路输出”等简称代替规则。

差异记录至少保留需求编号／位置、当前实现锚点、双方行为和待确认依据。它提供追溯入口，不代表需求已经满足、实现必然错误或差异已经获批关闭。

## 3 建议章节结构与承接关系

有效性与一致性回答数据能否参与处理、如何选用的问题；数值计算回答已取得的输入如何形成所需物理量；事件和指令处理回答操纵输入如何形成操作事件或持续指令。设备与系统状态则形成另一路状态报告。这些问题相关，但不是所有输入都必须顺序执行的同一套算法。

建议保留第三、四章的主体结构，新增两个专题；原第五章整体移至第七章并补充就绪判定，版本与验证范围移至第八章。这样既不将计算和指令处理强行塞入“有效性／一致性”，也不按每个输入量拆成独立章节。

| 建议章节 | 调整范围及读者需要建立的关系 |
|---|---|
| 1 信号状态、数据来源与总体处理关系 | 保留统一术语、来源身份和信息保留入口。补充数值计算、指令生成及就绪判定的输出关系；更新总体关系表，区分处理数据、生成指令和形成状态报告。 |
| 2 运行状态与策略控制 | 保留现有内容；只修订受章节编号变化影响的引用。 |
| 3 有效性处理与数据来源选择 | 保留异常确认／恢复、选源核心。增加多分量与业务资格规则、条件更新应用、导航输出层选源；扩充 3.3 的最终数值、有效性和通知对照。 |
| 4 一致性监测与数据表决 | 保留既有核心判据、参与通道、分支计算及应用差异；补需求差异的引用，不重写未受影响的算法。 |
| 5 数值转换与物理量计算 | 按“单位及正方向转换—死区与量程处理—导航物理量计算—执行器反馈标定”组织。每节解释本类计算的输入、公式、分支和输出；应用表说明参数与状态差别。 |
| 6 事件识别与指令状态更新 | 先建立输入变化与一次事件的关系，再说明脉冲延长；之后解释持续指令的置位、清除优先及历史保持。应用对照保留沿触发与电平更新的差别。 |
| 7 设备故障、冗余与系统就绪判定 | 保留原配置掩码和 SCU 故障组合；增加导航数据组连续有效确认、本机就绪条件及多机状态汇总。复用已解释的计数思想，说明不同判据和输出，不照搬异常锁存。 |
| 8 版本、需求对应差异与验证范围 | 保留修订／归档记录；集中说明第 2.3、2.4 节的待确认和差异事项，注明静态核查及未执行验证范围。 |

新增章节的开头应说明本章解决的设计问题、所接收的前序结果和输出用途，而不是逐条复述小节标题。第一章明确章节关系与实际连线关系的区别：例如 FTADC 经异常处理后可参与混合空速表决，表决结果可再被输出层选择；某些指令却直接依据有效操纵输入生成，并不经过空速比较。

第一章的结构概览只需补充具有代表性的结果记录，不复制完整 Bus 字段。必须分清：记录附带的 valid/reset、指令本身的布尔或编码值、独立状态报告，以及在当前应用中未继续传递的内部状态。不能把所有输出统一写成 data/valid/reset。

## 4 分步实施方案

### 第一步：冻结范围并核实待写细节

### 第二步：先完成已有章节的应用补充

### 第三步：撰写新增算法及系统状态内容

先写输入及输出关系，再按实际判据展开数值公式、事件历史或状态优先表。各节至少覆盖正常、输入无效、条件边界及历史处理；没有历史或恢复机制的方法明确按当前输入计算，不附加异常恢复流程。条件保护的效果可按连线推导，但阈值选取的工程原因没有依据时保持待确认。
