# VE25SP 模型设计说明

> 文档状态：局部设计草稿。2026-10-12 按有效性处理与来源选择、一致性监测与数据表决两条主线重组，保留运行状态控制和设备故障与冗余判定；状态、身份及位编码集中定义。实现事实以当前 `sp` 模型、库和字典为准；静态核对不替代模型运行或设计批准。

## 1 信号状态、数据来源与总体处理关系

<a id="signal-state-terms"></a>

### 1.1 术语定义与使用约定

本节统一后续算法章节使用的状态术语；数据来源与通道身份另见[第 1.2 节](#channel-identity)。**有效性、一致性、异常状态和选用结果分别回答不同问题，不能合并为一个互斥的“正常／异常”状态。** 同名 `valid` 在不同处理环节可能采用不同判据，正文中须说明其来源及使用条件。输入有效性、异常监测的接收许可和最终输出有效性，是相对于当前环节的定义，不构成所有信号必经的固定等级。

**表 1  信号状态与监测术语**

| 术语／标记                              | 定义                                                                                  | 使用边界                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 输入有效性`valid/Valid`               | 上游报告的数据或消息可用性；异常监测中以`g` 表示整体有效性，以 `d` 表示分项有效性 | 是本级算法的输入，不直接代表已通过本地比较或异常恢复确认                               |
| 输出有效性`validOut` 或输出 `valid` | 当前处理环节按自身使用规则形成的可用标志                                              | 异常监测表示允许接收；表决表示存在参与通道；来源选择采用所选数据的有效性               |
| 一致性`isSynced`                      | 数据与其他有效通道经过比较和连续确认后形成的数值一致状态，包含规定的历史保持          | 是相对于比较对象的判断，不表示时间戳同步；更换比较组合须重新评价                       |
| 配对失配／通道失配`isMissCompare`     | 配对失配表示两路持续超差；通道失配由与该路有关的配对结果综合形成                      | 与某一路配对失配，不必然使该通道被判为失配                                             |
| 异常状态`B/isAbnormal`                | `AbnormalMonitor` 根据分项无效的持续过程及恢复历史形成的状态                        | 不等于原始`valid` 取反；该算法不自行检查数值范围或多源差值                           |
| 禁用状态`isBanned`                    | 满足禁用条件后锁存的通道排除状态                                                      | 禁用使能关闭不清除已有锁存；本版所列一致性实例均关闭新增禁用                           |
| 来源编号                                | 指定从哪一路读取数据，例如`adahruSrc、RaSrc`                                        | 编号非零只表示确定了来源，各项数据是否可用仍看输出有效性                               |
| 参与通道掩码`chUsed`                  | 按位记录一个或多个实际参与表决的通道                                                  | 三路按 1、2、4 编码；与来源编号不是同一种编码，诊断`ChannelUsed` 应结合处理类型解释  |
| 复位通知`reset`                       | 按应用规则通知数据首次有效、恢复有效或来源／参与集合变化；部分应用也通知失去来源      | 是事件通知，不是健康等级，也不表示清除本模块全部内部状态；触发条件及是否输出由应用确定 |
| 历史数值保持                            | 不接收新数值时继续输出先前保存的数值                                                  | 保留数值不表示当前有效；输出无效是否保持数值，须依据具体算法判断                       |
| 设备故障状态                            | 设备上报或由设备状态组合形成的故障信息，如 MCU 故障等级、SCU 故障代码                 | 与比较失配、监测器内部异常状态分开定义；报告有效不代表设备正常                         |
| 冗余丧失标志`LossRedundancy`          | 按检查配置对指定状态位汇总得到的布尔结果                                              | 当前掩码算法不直接计算剩余设备数量；结果为假也可能是检查位被屏蔽                       |

后续章节沿用上述术语，并在各算法入口定义局部符号。本文以“拍”表示相应算法的一次执行；计数门限与实际时间之间的关系须结合各自计数结构和调度确认。

### 1.2 数据来源与通道身份

输入记录除数值及有效性外，还通过端口名称、总线成员或数组位置区分来源。`Curr/Current、Left、Right` 属于这种**结构中约定的通道身份**，用于区分同一数据项的不同候选记录；它们不是有效性或故障状态，也不一定以独立的身份字段随每项数据传递。

**表 2  数据身份的含义与边界**

| 身份信息                              | 含义                                                                                          | 使用边界                                                                         |
| ------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 相对通道`Curr/Current、Left、Right` | 本机视角下的当前、左、右逻辑通道位置；`Curr` 常用于端口后缀，`Current` 常用于内部总线成员 | 不直接表示飞机安装位置、左／右操纵杆，也不能按名称固定等同于 FCC1／FCC2／FCC3    |
| FCC 编号`fccId、activeFccId`        | GCS 选源使用的本机编号及主控 FCC 身份                                                         | 通过映射确定优先输入位置；两字段编码不同，不能把编号值直接当作输入序号或参与掩码 |
| 测量设备或协议源节点身份              | 标识原始测量设备或报文发送节点，例如 ADAHRU、RA 的设备源号和地面站协议的消息源节点            | 与接收、采集或转发通道属于不同维度；多份候选记录不等于多个独立物理信息源         |

**各处理链保留身份的阶段不同。** 输入按通道区分，不代表最终数值输出仍携带全部原通道信息。

**表 3  通道身份的处理与保留**

| 数据类别         | 输入组织与本地处理                                                                                                                                                   | 输出中的身份信息                                                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 飞行员杆位、按键 | `VDT_Stick_Curr/Left/Right`、`Dis_Key_Curr/Left/Right` 各含同构业务字段；同一项按 `Current、Left、Right` 顺序组成三路，进行比较与表决                          | `VDT`、`GPIO` 输出按业务项保留 `data/valid/reset`；逐路身份及表决参与掩码不附在最终数据中                                                                                    |
| 地面站操纵信息   | `SpIn_Gcs_Curr/Left/Right` 是三份候选记录；`RemotePilotCtrl` 与 `RemoteFMCP` 按各自有效性和优先输入位置分别选源，不作三路业务数值比较                          | `GcsData` 保留选定业务数据及其有效性、复位信息；两组选源的内部 `voterState` 均被终止，来源诊断不随该总线输出                                                                   |
| 系统状态         | `Sys_Status_Curr/Left/Right` 以 `SpIn_CcdlMsg` 输入，经 `Calc_SysInfo` 按各路 `Valid` 分别处理就绪状态和限制派遣信息；`SpIn_SysInfo_Curr` 是另一路本机输入 | 中间总线`SysInfoData` 保留 `Current/Left/RightSysReady` 及 `Current/Left/RightLimitDispatchInfo`；后续汇总为 `SysReady/LimitDispatch`，控制律 SYS 接口不保留这六个分路字段 |
| 导航测量         | ADAHRU 的同类数据以三元素数组组织，RA 高度以两元素数组组织                                                                                                           | 候选下标用于区分设备数据，选用来源及诊断另行封装；设备源号到模型数组下标的上游适配关系须另核对                                                                                     |

例如，`VDT_Stick_Curr.CSSU_X` 与 `VDT_Stick_Left.CSSU_X` 是同一杆位量在两个逻辑通道中的记录；`CSSU_X`、`RSSU_X`、`LSSU_X` 才用于区分不同操纵装置的业务项。不能将外层 `Left` 与内层 `LSSU` 混为一义。表决后的操纵数据项仍通过数组位置区分，并由控制律接口转换为相应字段；不再保留的是同一项的三路候选结构。

GCS 中可以直接确认 FCC 身份到候选位置的映射。例如，`fccId=0` 且 `activeFccId=PFCC2` 时，优先位置为 `Right`；该组 `Right` 输入有效时才选用它。该映射说明选源控制如何定位输入，不证明地面站指令由 FCC2 产生，也不能直接推广为 VDT 或 Sys 输入的物理接线表。GCS 的位置号 `1/2/3` 与第 1.1 节的参与掩码 `1/2/4` 须分别解释。

#### 接口依据与适用范围

FICD 为操纵输入的采集和传递提供以下依据：

- 综合开关附件 01-03《4-离散量功能逻辑表》`J2/J3/J4/J6/J8` 要求三台 FCC 分别监控三个开关通道并表决；侧杆离散量附件 01-08 同名表 `D2/E2/J2` 给出 TRC 的三 FCC、三余度及表决要求。因此，可在设备边界上描述为“FCC 采集／监控相关操纵输入”；SP 接收并处理采集后的软件记录。

### 1.3 状态关系与输出保留

状态能否同时成立，应在同一数据、同一处理环节下判断。表 4 给出本版实现中的典型关系，接收与恢复条件在第 3.1 节说明，比较状态及表决资格在第 4.1、4.2 节说明。

**表 4  状态共存与互斥关系**

| 条件或场景                                                           | 可以同时出现的状态                                                                              | 后续影响                                                     |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| ADAHRU 某路 CAS 失配已经确认，上游仍报告有效                         | 输入`valid=true`、`isMissCompare=true`、`isSynced=false`                                  | 预处理保留原始有效性；当前严格空速表决排除该路               |
| 仅一路有效，缺少有效比较对象                                         | 输入`valid=true`、`isSynced=false`、`isMissCompare=false`                                 | 无一致性支持不等于已确认失配；是否允许单路使用由表决策略决定 |
| FTADC CAS 整体持续有效，异常已确认，分项有效性恢复但恢复计数未达门限 | 原始`valid=true`、内部 `B=true`、输出 `valid=false`                                       | 继续保持历史数值，等待恢复确认                               |
| FTADC CAS 整体有效、此前无异常，分项刚出现无效且异常计数尚未达门限   | 原始`valid=false`、内部 `B=false`、输出 `valid=false`                                     | 立即停止更新，但尚未确认持续异常                             |
| 同一`CmpMonitor` 通道输出                                          | `isSynced=true` 要求本路有效且未失配、未禁用                                                  | 该路一致状态不能与通道失配或禁用状态同时为真                 |
| SCU 整体输入无效                                                     | `Position.valid=false`；故障报告的 `FaultStatus.valid=true`、`ClawFaultStatus.valid=true` | 位置不可用与故障报告可用可以同时成立，代码判据见第 5.3 节    |

状态的生成位置与最终保留位置也应分别说明：

**表 5  监测信息的生成与保留**

| 处理路径                  | 本地生成或使用的信息                             | 输出保留方式                                                                                               |
| ------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| ADAHRU／RA 预处理及选源   | 逐路`valid、isSynced、isMissCompare、isBanned` | 预处理输出正常化数据和诊断状态；选源后的数值输出为`data/valid/reset`，三路诊断及来源信息另行封装         |
| VDT／GPIO 表决            | 三路比较状态与表决参与集合                       | 比较状态在模块内部使用，最终输出`data/valid/reset`；逐路比较状态及参与掩码不附在最终数据中               |
| 混合来源空速              | 对新组合重新计算三路比较状态                     | 一致状态用于表决；失配、禁用引出端及参与掩码未继续输出                                                     |
| FTADC／MPIO／MCU 异常监测 | 内部异常`B`、接收许可和历史数值                | 本版所列实例均将`isAbnormal` 引出端终止，最终数据保留 `data/valid/reset`；`reset` 的外围规则各不相同 |

因此，最终输出中没有某个标签，不代表处理链没有执行对应监测；输出为无效，也不能反推出唯一的失效原因。

### 1.4 状态字与位掩码约定

位编码是记录多个布尔条件的表示方式，具体判定仍由表决、故障检测或配置规则完成。通道位掩码按位权 1、2、4 表示三路，某位为 1 的含义须由变量定义；相同数值不能跨变量解释为相同状态。

**表 6  位掩码的用途与解释**

| 变量                         | 位为 1 的含义                                          | 产生与使用                                               |
| ---------------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| `chUsed`                   | 对应通道实际参与表决                                   | 第 4.2 节根据有效性与一致性确定；可同时置多个通道位      |
| `VdtCBIT`                  | 对应 Current／Left／Right 通道的指定杆位有效性检查失败 | 第 5.2 节说明检查对象；用于冗余状态判定                  |
| `check_VDT_Bit` 等检查掩码 | 允许对应状态位参与本次汇总                             | 配置输入；屏蔽检查位不清除原状态位                       |
| 选源诊断`ChannelUsed`      | 编码所选单一路径                                       | 本文单源应用采用 1／2／4；是否受有效性约束由具体实现决定 |

例如，在操纵输入应用中，数值 2 对 `chUsed` 表示选用 Left，对 `VdtCBIT` 表示 Left 检查失败，对 `check_VDT_Bit` 表示仅检查 Left。以下 `stateBits` 则按不同状态属性分配位号，须与通道位掩码分开解释。

#### 一致性诊断状态字

`tSignalState` 包含 `lastTimestamp` 和 `stateBits`。在 ADAHRU／RA 当前使用的 `Calc_SignalState` 及双精度封装中，`lastTimestamp` 固定为 0，状态字实际按下式形成：

```text
stateBits = valid + 2×isSynced + 4×isMissCompare + 8×isBanned
```

该表达式说明上述封装的实际写入，不作为所有 `tSignalState` 使用位置的统一位定义。当前模型与字典注释存在以下差异：

**表 7  当前一致性封装与字典注释的差异**

| 位号（从 0 开始） | 一致性封装实际写入 | `SP_State.sldd` 字段注释                |
| ----------------: | ------------------ | ----------------------------------------- |
|                 0 | `valid`          | `valid`                                 |
|                 1 | `isSynced`       | `updated`                               |
|                 2 | `isMissCompare`  | `isTimeout`                             |
|                 3 | `isBanned`       | `isAbnormal`                            |
|              4～6 | 该封装不写入这些位 | `isOutOfRange、isMissCompare、isBanned` |

例如，该封装的 `stateBits=5` 表示“有效且失配”，不能按字典注释解释为“有效且超时”。**当前文档按实际写入解释该链路；统一位定义及下游解析的一致性仍待工程确认。** 本次不修改模型或字典来消除这一差异。

依据：[SignalProcessingLib.slx](D:/666/VE25/sp/04_Design/common/specification/block_libraries/SignalProcessingLib.slx) 的 `SignalStateSet_New` SID 2514、常量 SID 2524／2529／2530／2531；[SP_State.sldd](D:/666/VE25/sp/04_Design/common/libs/sldd/SP_State.sldd) 的 `tSignalState`。完整字段结构参见 [Bus 信号结构说明](D:/666/VE25/Doc/VE25SP_Bus信号结构说明.md)；算法章节另说明各字段的实际产生与使用。

### 1.5 总体处理关系

本说明以有效性和一致性为两条数据处理主线。有效性处理根据输入有效标志及适用的异常历史，决定是否接收数据、何时恢复及无效期间如何输出；来源选择依据有效性、优先关系和来源历史确定单一路径。一致性监测比较有效候选数据，形成逐路一致、失配和禁用状态；表决据此结合输入有效性确定参与集合，再计算结果。

有效性同时是参与比较的条件，两条主线通过数据及状态连接。第三章集中说明有效性处理与来源选择，第四章集中说明一致性状态产生及表决使用；运行状态与策略控制、设备故障与冗余判定分别保留独立章节。各方法先说明判据、分支和历史状态，再说明应用、参数绑定、数值转换与输出装配。

| ------------------ | --------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------ |

## 2 运行状态与策略控制

### 2.1 设计目标与分类机制

本模块读取 `vtolState`，将运行状态划分为地面类和飞行类，输出 `OnGnd`，供后续选源和比较监控使用。设本拍状态为 `r`，采用地面策略的状态集合为 `G`，则：

```text
OnGnd = (r 属于 G)
inAir = NOT OnGnd
```

分类以本拍接收状态计算，不含本地锁存、延迟或连续确认。同类状态之间变化不改变分类结果；跨类别变化在本次分类计算中产生新结果。分类模块不负责外部状态的进入／退出判定，也不以该映射独立检测物理离地。

### 2.2 VTOL 状态映射与输入接口

本应用输入为 `RmsPublicMsg.vtolState`，总线类型为 `BUS_DRMS2SP_MSG`，字段为标量枚举 `ENUM_DRMS_VTOL_STATE`。输出 `OnGnd` 为布尔量；集合 `G` 由下表中五个地面成员构成。

当前枚举定义包含九个成员。表 9 覆盖全部已定义成员，说明每个输入状态对应的分类和输出。

**表 9  VTOL 运行状态到地面／飞行类别的映射**

| 输入枚举成员  | 编码 | 本模块采用的类别 | `OnGnd` |
| ------------- | ---: | ---------------- | --------- |
| `Unknown`   |    0 | 地面             | `true`  |
| `Disarm`    |    1 | 地面             | `true`  |
| `Arm`       |    2 | 地面             | `true`  |
| `MtrCheck`  |    3 | 地面             | `true`  |
| `SurfCheck` |    4 | 地面             | `true`  |
| `LiftOff`   |    5 | 飞行             | `false` |
| `MC`        |    6 | 飞行             | `false` |

实现对前五个枚举成员分别进行相等比较，并将结果作逻辑或运算。因此，未解锁、已解锁及检查等状态在本分类中采用地面策略；从 `LiftOff` 类别开始采用飞行策略。例如，`Arm` 归为地面类，体现了“已解锁”和“进入起飞／飞行阶段”的区别。枚举名称用于解释运行阶段，本模块不定义这些状态之间的转换顺序。

消息更新时机及输入可用性由接口链路另行规定。

`Unknown` 被明确映射为地面类。这只能说明当前实现对未知状态采用地面处理策略，不能据此认定飞机物理上处于地面。输入未取得、报文超时和非法编码是否会被上游转换为 `Unknown`，本节尚无依据确认。

分类结果在三个下游位置使用。表 10 说明其作用范围，其中选源策略仅概括与本分类直接相关的行为。

空速分支中的 `inAir` 是比较监控的一个条件，不能将该连接概括为“地面关闭全部空速比较监控”。其作用仅为第 4.1 节中新增禁用状态的许可条件。

## 3 有效性处理与数据来源选择

本章说明有效标志如何影响数据接收、失效处理、恢复及来源选择。第 3.1 节按即时处理和连续异常监测解释数值与状态的输出，第 3.2 节解释多路候选数据的来源判定，第 3.3 节对照各路径的输出行为。

各方法按应用调用：FTADC、MPIO 指定三项及 MCU 转速／功率采用异常监测；ADAHRU、RA、GCS 执行各自的来源选择；MPIO 的 24 项业务字段、MCU 的 FaultLevel／WorkMode 及 SCU 位置按接口规则直接封装。来源选择可以直接读取候选数据的有效性，无须先经过异常监测。FTADC 空速处理后进入混合来源表决的连接关系，见第 4 章。

### 3.1 有效性处理与异常恢复

#### 3.1.1 设计目标与接口约定

本节采用[第 1.1 节](#signal-state-terms)的整体／分项有效性、异常状态与数值保持定义。第 3.1.2 节说明直接封装、即时门控和默认输出；第 3.1.3～3.1.4 节说明连续异常监测及数值保持，第 3.1.5～3.1.6 节说明 FTADC、MPIO 和 MCU 的调用差异。

连续异常监测检查整体有效标志和每项数据的有效标志。整体或某项数据无效时，该项立即停止更新，保持上次输出数值，并输出无效标志。整体保持有效时，分项连续无效的计数用于确认异常；异常确认后，须连续有效达到恢复门限才重新接收数据。

输入量包括整体有效性 `g`、分项有效性 `d`、当前数值 `dataIn` 和历史数值初值 `data0`。配置量 `A` 为异常确认门限，`R` 为已确认异常后的恢复门限。库输出包括异常状态 `B`、接收许可 `validOut` 和处理后的数值。外围决定是否输出异常诊断及如何生成 `reset`；FTADC 检测有效性上升沿，MPIO、MCU 当前将 `reset` 固定为 `false`。

**表 12  异常监控的配置作用**

| 配置量    | 控制作用与边界                                                                  |
| --------- | ------------------------------------------------------------------------------- |
| `A`     | 连续异常计数的确认门限；`A<=0` 时关闭异常状态判定，接收许可仍要求 `g AND d` |
| `R`     | 异常历史的恢复确认门限；`R<=0` 时取消恢复等待，异常置位条件仍单独生效         |
| `data0` | 尚未接收数据时使用的数值历史初值，不决定输出有效性                              |

#### 3.1.2 即时有效性处理与接口装配

##### 数据无效时的输出规则

即时有效性处理只根据本拍有效性封装或门控输出，不保存异常计数和数值历史。表 13 列出各接口的处理差异，并以连续异常监测的保持行为作对照；两者是不同的应用方式。设计说明须分别交代数值与状态，不能由 `valid=false` 推定数值一定保持、清零或停止变化。

**表 13  数据无效时的处理差异**

| 处理路径                   | 数值或状态输出                                                             | 有效性与通知                                   |
| -------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------- |
| 第 3.1.3～3.1.6 节异常监测 | 不接收新值，保持末次接收值或初值                                           | 输出无效；恢复按异常历史判定，通知由外围决定   |
| SCU 位置反馈               | `Position_Fdb` 本拍数值直接写入 `Position.data`                        | `valid=SCU.Valid`；`reset=false`           |
| MCU 故障等级、工作模式     | 原`McuFaultLevelFbk/McuWorkModFbk` 直接写入 `FaultLevel/WorkMode.data` | `valid=MCU.Valid`；`reset=false`           |
| MPIO 直接封装字段          | 本拍业务数值或状态码继续传递                                               | `valid=SpIn_MpioInfo.Valid`；`reset=false` |

#### 3.1.3 连续确认与异常状态

##### 连续条件计数

设置两个独立计数器，输出分别为异常计数 `errorCnt` 和恢复计数 `resumeCnt`。

**表 16  连续计数的累积与清零条件**

| 计数输出      | 累积条件               | 清零条件               | 输出限幅范围      |
| ------------- | ---------------------- | ---------------------- | ----------------- |
| `errorCnt`  | `g=true AND d=false` | `g=false OR d=true`  | `0 ～ max(A,0)` |
| `resumeCnt` | `g=true AND d=true`  | `g=false OR d=false` | `0 ～ max(R,0)` |

每条计数链采用单拍 Delay 存储历史值，初值为 0；Delay 输出经动态限幅后形成计数输出，同时加 1 反馈至 Delay 输入。Delay 的外部复位方式为 `Level hold`，表 16 的清零条件成立时复位到初值。条件中断即清零，使判定依据保持为连续过程，零散出现的无效或有效状态不会累计形成确认。

限幅上限使用 `max(门限,0)`，保证上限不低于下限 0；门限为负时，上下限均为 0。该非负限幅与异常状态中的 `A>0` 使能判断分别承担数值约束和功能使能的职责。

##### 异常状态保持与判定优先级

异常判定使用单拍历史保存上一拍异常状态，初值为 `false`。记本拍异常状态为 `B`、上一拍为 `B_prev`，实现关系如下：

```text
B = g AND (A > 0)
    AND ((errorCnt >= A)
         OR (B_prev AND NOT(resumeCnt >= R)))

validOut = g AND d AND NOT B
```

异常计数达到 `A` 时置位 `B`；异常已经置位且恢复计数尚未达到 `R` 时，通过历史反馈保持异常。恢复计数达到门限后，恢复选择支路切断历史异常保持。整体 `g=false` 或 `A<=0` 时，外层门控直接清除异常状态。

判定顺序为：**整体有效性及异常使能 → 异常置位 → 恢复清除 → 历史保持**。异常置位支路与历史保持支路作逻辑或运算，因此异常置位优先于恢复清除。两个门限均为正数时，两类计数的清零条件互补，正常布尔输入下不会同时达到两个正门限。

`validOut` 同时受本拍 `g`、`d` 和异常状态约束。单项或整体输入一旦无效，接收许可立即撤销；异常计数门限用于确认持续失效，而不延迟无效数据的屏蔽。已确认异常后，即使原始有效标志恢复，也须完成恢复确认才能重新接收数据。

##### 联合分支处理

表 17 在 `A>0、R>0` 条件下说明状态判定与数值处理的对应关系。数值动作由第 3.1.4 节根据 `validOut` 统一执行。

**表 17  异常状态、接收许可与数值处理**

| 输入及历史条件                                       | 当前异常状态`B` | `validOut` | 数值动作     |
| ---------------------------------------------------- | ----------------- | -----------: | ------------ |
| 整体`g=false`                                      | 清除；两计数复位  |    `false` | 保持历史数值 |
| `g=true、d=false`，此前无异常且异常计数未达 `A`  | 尚未确认异常      |    `false` | 保持历史数值 |
| `g=true、d=false`，异常计数达到 `A` 或此前已异常 | 置位或保持异常    |    `false` | 保持历史数值 |
| `g=true、d=true`，此前无异常                       | 正常              |     `true` | 接收当前数值 |
| `g=true、d=true`，此前已异常且恢复计数未达 `R`   | 保持异常          |    `false` | 保持历史数值 |
| `g=true、d=true`，此前已异常且恢复计数达到 `R`   | 清除异常          |     `true` | 接收当前数值 |

由该结构可推导出两种恢复路径：尚未形成异常历史时，有效输入可直接接收；已确认异常时，须等待恢复计数达到门限。恢复期间再次无效会清零恢复计数，下一次恢复重新计数。启动后若持续无效已形成异常历史，则第一次出现有效输入也须完成恢复确认。

正门限配置下，增大 `A` 会延后异常状态确认，但无效输入仍立即停止更新；增大 `R` 会延长已确认异常后的恢复等待。

#### 3.1.4 数值保持与有效性恢复通知

接收许可 `validOut` 同时控制数值更新并作为输出有效性，使数据接收与有效性使用同一判据。

数值更新在当前输入与上一拍输出之间选择，选择结果既对外输出，也回写单拍历史：

```text
validOut=true  ：dataOut = 当前 dataIn
validOut=false ：dataOut = 上一拍 dataOut
```

数值历史以应用提供的 `data0` 初始化，尚未接收有效数据时保持该初值；接收过有效数据后，后续失效保持末次接受值。数值保持环节没有独立外部复位端口，因此整体无效虽然清除计数和异常状态，仍保留数值历史。整体随后恢复且单项有效时，此前异常已被清除，可重新接收数据。

保持期间 `validOut=false`，历史数值的保留不表示当前数据有效。输入数值只参与更新与保持，异常判定路径不包含物理量范围或多源差值检查。

`AbnormalMonitor` 本身不产生 `reset`。需要恢复通知的外围可另用一个初值为 `false` 的单拍历史保存上一拍输出有效性，按下式生成；第 3.1.5 节 FTADC 采用此方式：

```text
reset = 当前 validOut AND NOT 上一拍 validOut
```

采用上述通知方式时，首次有效、短暂失效后恢复有效，以及异常恢复确认完成时，`reset` 置位一个执行拍；持续有效或当前无效时为 `false`。该字段表示数据首次有效或由无效恢复为有效，只送入输出封装，不反馈至监控子系统。内部计数清零、异常状态清除和对外 `reset` 通知由不同逻辑完成。

### 3.2 数据来源选择

#### 3.2.1 功能与处理过程

本节的来源编号、输出有效性和复位通知采用[第 1.1 节](#signal-state-terms)定义；选定来源与确认数据有效分别判断。

数据来源选择用于从多路同类数据中选出一路供后续使用。算法根据数据有效性、优先顺序及适用的历史保持规则确定本拍来源，再提取所选数据。应用封装决定输出有效性、来源变化通知以及是否保留来源诊断。

处理顺序为：**来源判定 → 数据提取 → 有效性与变化通知 → 输出封装**。来源可以采用编号或单路掩码表示，须按各应用定义解释。导航选源读取各数据项的有效性，GCS 则按消息组分配有效性。

当前应用包括 ADAHRU、无线电高度（RA）和地面站消息（GCS）。ADAHRU 与 RA 共用 `SignalProcessingLib/SrcSelect`，其规则见第 3.2.2 节；GCS 采用独立的整组消息选择和通知逻辑，见第 3.2.6 节。设备分级、公共来源与 CAS 专用来源属于 ADAHRU 应用的规则。

#### 3.2.2 数据提取、复位与诊断封装

本节说明 ADAHRU、RA 共用的 `SrcSelect` 规则，不将其复位及诊断行为推广到第 3.2.6 节 GCS。

来源判定得到编号 `index` 后，逐项选择器读取该通道本拍的 `data` 和 `valid`。选择器不对多路数值求平均，也不在输入无效时保持历史数值；即使来源编号继续沿用，读取的仍是所选通道本拍的数值。

记本拍来源编号为 `index[k]`，有效来源编号为 `e[k]`：

```text
e[k] = index[k]，当所选数据 valid=true
e[k] = 0，       当所选数据 valid=false

reset[k] = valid[k] AND (e[k] != e[k-1])
```

有效来源历史初值为 0。首次有效、切换到另一有效来源及无效后恢复有效时均产生复位通知；持续有效且来源不变、或本拍无效时不产生通知。即使来源编号未变，有效性恢复仍会触发。各数据项依据自身有效性历史分别产生复位通知。

来源判定保存的“上一拍来源”用于决定本拍是否换源；此处保存的“上一拍有效来源”用于生成复位通知。前者可以在数据无效时保留原编号，后者在本拍数据无效时记为 0，因此能够识别同一路数据失效后的恢复。

选定数值及 `valid/reset` 由调用模块封装为数据输出。调用模块另根据来源编号生成 `voterState`，通过 `SrcSelect` 的第三输入传入；`SrcSelect` 将其与三路输入 `state` 组成诊断输出。当前两类应用均填写 `VoterType=SourceSelect`，并将来源编号 1、2、3 编码为 1、2、4：

```text
tRedundantDataState
├─ ch1SignalState : tSignalState，保留第 1 路输入 state
├─ ch2SignalState : tSignalState，保留第 2 路输入 state
├─ ch3SignalState : tSignalState，保留第 3 路输入 state
└─ voterState     : tVoterState
   ├─ VoterType   : Enum_VoterType，填写 SourceSelect
   └─ ChannelUsed: uint8，按来源编号 1、2、3 编码为 1、2、4
```

来源编号 1、2、3 与诊断编码 1、2、4 分别表示同一组通道，但编码方式不同。`ChannelUsed` 不受输出 `valid` 门控，非零只表示已选定来源，不能据此判定数据有效。该单源编码也不能直接替代第 4.2 节表决中的多通道参与掩码。

#### 3.2.4 ADAHRU 导航数据选源

##### 3.2.4.1 输入数据与处理关系

本应用先评价三台设备的数据有效性，再确定公共来源和 CAS 专用来源，最终输出选定数据、诊断状态、设备等级及公共来源编号。

输入为 `adahruNormalInfos:BUS_adahruNormalInfos` 和地面／飞行分类 `OnGnd`。输入包含 31 类信号，每类均为三路数组，各路携带 `data`、`valid`、`isSynced` 和 `state`。组合纬度、经度使用 `Bus_DoubleSignalNormalInfo[3]`，其余 29 类使用 `Bus_SingleSignalNormalInfo[3]`。

**公共来源**是除 CAS 外其余 30 类导航数据共同采用的设备来源。**CAS 专用来源**是单独选定的空速来源：优先使用公共来源的空速；该路空速无效时，再从其他设备中选择有效空速。两种来源分别送入对应的数据选择器。

##### 3.2.4.2 设备有效性评价

对每台设备，先按表 25 检查惯性、速度／航向和位置数据是否有效，再按表 26 给出 1～4 级的设备有效性等级。等级越高，选源优先级越高。所有条件仅读取相应信号的 `valid`，不读取 `isSynced` 或 `stateBits`，CAS 也不参与设备等级计算。

**表 25  设备有效性条件**

| 条件                  | 成立要求                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| 惯性条件`C_I`       | `Pitch`、`Roll`、`SforX`、`SforY`、`SforZ`、`Q`、`P`、`R` 全部有效                            |
| 速度／航向条件`C_N` | `NorthVelocity`、`EastVelocity`、`TrueHeaading` 全部有效，且 `GpsAltRate`、`AdAltRate` 至少一项有效 |
| 位置条件`C_P`       | `GpsHeight`、`CombLate`、`CombLong` 全部有效                                                            |

`GpsAltRate` 与 `AdAltRate` 的“至少一项有效”针对同一设备内的两种高度变化率。`TrueHeaading` 为模型字段的实际拼写。

**表 26  设备等级判定**

| 等级`W` | 条件                        | 具备的有效数据组                                 |
| --------: | --------------------------- | ------------------------------------------------ |
|         4 | `C_I AND C_N AND C_P`     | 惯性、速度／航向、位置均完整                     |
|         3 | `C_I AND C_N AND NOT C_P` | 惯性与速度／航向完整，位置不完整                 |

三台设备的等级形成 `AdahruWeight=[W_1,W_2,W_3]`，类型为 `uint8[3]`。接口中的 `Weight` 表示设备有效性等级，用于决定优先选用哪台设备，不参与数值加权计算。

该分级依次以惯性、速度／航向和位置数据的完整性提高等级。因此，某项数据失效是否引起换源，取决于它是否改变设备等级以及三路等级的相对关系。

##### 3.2.4.3 公共来源选择

先比较三台设备的等级，选择等级最高的设备。多台设备等级相同时，根据 `OnGnd` 决定采用固定顺序，还是继续使用上一拍选中的设备：

**表 27  公共来源选择规则**

| 条件                                                | 选择规则                                |
| --------------------------------------------------- | --------------------------------------- |
| `OnGnd=true`                                      | 在最高等级设备中按第 1、2、3 路顺序选择 |
| `OnGnd=false`，上一拍来源仍具有最高等级           | 保持上一拍来源                          |
| `OnGnd=false`，上一拍来源不具有最高等级或尚未建立 | 在最高等级设备中按第 1、2、3 路顺序选择 |

选择结果 `adahruSrc` 为 `uint8` 标量，取值 1、2、3 分别表示三台设备。该编号通过一个单拍延迟保存为 `lastSelect`，初值为 0。首次执行时，选择等级最高且编号最小的设备；本模块没有额外的换源连续确认计数。

三路均为等级 1 时仍按上述规则选出来源：地面选择第 1 路，飞行时保留上一拍已建立的来源，首次选择第 1 路。因此，`adahruSrc` 非零只表示已确定来源，各项数据是否可用仍须依据其输出 `valid`。

因此，飞行中另一台同等级设备恢复有效时，可以继续使用当前设备；另一台设备的等级更高时，则切换到等级更高的设备。

##### 3.2.4.4 CAS 专用来源选择

设备等级计算不包含 CAS，因此等级最高的设备也可能没有有效空速。`CAS_Select` 据此单独选择空速来源。记公共来源为 `s`，CAS 专用来源为 `c`，按以下顺序处理：

1. 若第 `s` 路 `CAS.valid=true`，则 `c=s`。
2. 否则，按第 1、2、3 路顺序选择第一路有效 CAS。
3. 若三路 CAS 均无效，则保持上一拍 CAS 来源编号；该编号初值为 1。

这里仅以 `CAS.valid` 为选择条件，不要求 `CAS.isSynced=true`。因此，单源 CAS 可与独立空速表决采用不同通道，CAS 来源也可与其他导航数据的公共来源不同。

三路空速均无效时，只保留原来的**来源编号**。后级仍读取该设备本拍的 `data`，并输出 `valid=false`。这里不保持上一拍有效空速；第 4.2 节表决在没有通道参与时才保持历史数值。

##### 3.2.4.6 单源空速与表决空速示例

以下示例同时说明参与集合、公共来源和 CAS 来源之间的关系。数值均为缩放前的输入数值，不附加未确认的工程单位。

假设本拍三路 CAS 为 `[100,102,130]`，`valid=[true,true,true]`，`isSynced=[true,true,false]`；设备等级为 `[3,3,4]`。上一拍表决参与掩码为 7，单源 CAS 已使用有效的第 3 路。

- **空速表决：**`q=[1,1,0]`，形成 `chUsed=3`，进入 case 3，得到 `(100+102)/2=101`。参与集合由 7 变为 3，输出 `VoterCAS_mps={data:101/3.6, valid:true, reset:true}`。
- **来源选择：**第 3 路等级最高，公共来源为 `adahruSrc=3`；其 CAS 有效，CAS 专用来源也为 3。有效来源未变，输出 `adahruCAS_MPS={data:130/3.6, valid:true, reset:false}`。
- **诊断状态：**CAS 来源编号 3 编码为 `ChannelUsed=4`；独立表决的 `chUsed=3` 则表示通道 1、2 的组合。

本例中，`adahruSrc=3` 与 `chUsed=3` 虽然数值相同，分别表示第 3 路来源和第 1、2 路参与集合。两类输出采用不同资格条件，因而可同时有效且数值不同。

#### 3.2.6 地面站消息选源

##### 输入分组与优先来源

地面站输入按第 1.2 节的 Current／Left／Right 三个候选位置组织。`RemotePilotCtrl` 与 `RemoteFMCP` 分别依据 `PilotCtrlMsgValid`、`FmcpMsgValid` 选源；两组共享优先位置，但独立判断有效性，因此可以采用不同来源。

优先位置由本机 `fccId` 和主控 `activeFccId` 映射产生，位置 1／2／3 分别对应 Current／Left／Right。

**表 32  FCC 身份到优先输入位置的映射**

| 本机 fccId | activeFccId=PFCC1 | PFCC2        | PFCC3        |
| ---------: | ----------------- | ------------ | ------------ |
|          0 | Current（1）      | Right（3）   | Left（2）    |
|          1 | Left（2）         | Current（1） | Right（3）   |
|          2 | Right（3）        | Left（2）    | Current（1） |

##### 选源判定与数据提取

每组消息按以下顺序处理：

1. 优先位置对应的消息有效时，选择该路。
2. 否则按 Current→Left→Right 选择第一路有效消息。
3. 三路均无效时，来源掩码 `h=0`，输出有效性为 `false`。

这里 `h=1/2/4` 分别表示 Current／Left／Right，只有一路入选。位置号 1／2／3 与来源掩码 1／2／4 不可混用。该实现不进行三路业务数值比较，也不使用上一拍来源保持同级优先权；历史只用于检测来源变化。

数值路径按 `h=2` 读取 Left、`h=4` 读取 Right，其余情况读取 Current。因此全无效时，仍输出 Current 本拍消息的数值并置 `valid=false`，不保持上次有效消息，也不替换为零值。

##### 有效性与来源变化通知

两组选源内部均保存上一拍来源掩码，初值为 0，并计算：

```text
valid = (h > 0)
reset = (h[k] != h[k-1])
```

该变化通知未附加有效性门控：首次建立来源、有效来源切换及非零来源变为 0 均产生通知；来源掩码不变时不产生通知。与第 3.2.2 节的 `SrcSelect` 不同，此处事件还包括失去有效来源。

## 4 一致性监测与数据表决

本章沿数据使用关系说明一致性状态如何产生并影响表决。一致性监测先检查配对资格，再根据数值偏差及其连续过程形成逐路状态；表决结合输入有效性与一致状态确定参与掩码 chUsed，再由该掩码选择数值分支、生成输出有效性并检测参与集合变化。

第 4.1 节集中说明比较、连续确认和通道历史，第 4.2 节集中说明参与资格、分支计算和表决输出。各应用的调用、参数、转换及诊断保留在对应算法小节列出。监测结果也可用于诊断：第 3.2 节的 ADAHRU／RA 来源选择读取有效性，不以一致状态作为选用条件。

### 4.1 三通道一致性监测

#### 4.1.1 设计目标与接口约定

本节沿用[第 1.1 节](#signal-state-terms)的有效性、一致性、失配与禁用定义。算法对同一数据项的三路输入进行两两比较，根据偏差及其持续过程形成每路的一致、失配和禁用状态。这些状态供后级表决或诊断使用；各应用是否以一致性限制数据使用，见应用说明。监控实例各自保存计数和通道历史；使用同一算法或参数不共享实例状态。

输入包括三路数值 `x_i`、各路有效标志 `v_i` 和 `inAir`，其中 `i=1、2、3`。`inAir` 控制是否允许将通道置为禁用，实际禁用还须满足禁用使能和失配条件。参与比较的数据应使用相同数值尺度；精度选择和必要转换由应用封装完成。输出为逐通道的一致状态 `isSynced`、失配状态 `isMissCompare` 和禁用状态 `isBanned`。

#### 4.1.2 配置参数

**表 36  一致性监控参数**

| 参数          | 算法作用                                                 |
| ------------- | -------------------------------------------------------- |
| `MAXERROR`  | 两路数值允许的最大绝对差，单位与比较数据相同             |
| `MISSCMP`   | 配对失配请求的连续超差确认门限                           |
| `BANNED`    | 配对禁用请求的连续超差门限，与失配请求使用同一失配计数器 |
| `SYNCED`    | 配对一致请求的连续一致确认门限                           |
| `BANENABLE` | 大于 0 时允许新置位通道禁用；关闭使能不清除已有禁用历史  |

误差门限限定容许偏差，连续计数门限确认偏差或一致关系是否持续。禁用请求和通道禁用状态分层产生，后者还受两组配对请求、`inAir` 和禁用使能约束。

#### 4.1.3 核心判定与状态更新

##### 配对有效性与偏差判定

设置三组配对，分别比较 **(1,2)、(2,3)、(3,1)**。

某一路参与比较的条件为：**输入有效性 `v_i=true`，且上一拍未被禁用**。一对通道双方均满足该条件时，该**配对有效**。

记两路数据为 `x_i`、`x_j`，计算绝对差：

`e_ij = |x_i - x_j|`

本拍数值一致的判据为：

`e_ij ≤ MAXERROR`

##### 连续确认与配对请求

每个比较器设置连续一致计数 `c_s` 和连续失配计数 `c_m`，初值均为 0。

**表 37  配对有效时的计数更新**

| 本拍比较结果         | 一致计数`c_s`            | 失配计数`c_m`                             |
| -------------------- | -------------------------- | ------------------------------------------- |
| `e_ij <= MAXERROR` | 加 1，最大保持在`SYNCED` | 清零                                        |
| 上述条件不成立       | 清零                       | 加 1，最大保持在`max(MISSCMP, BANNED, 0)` |

首个满足条件的执行拍计为 1。本拍使用更新后的计数产生请求：

```text
失配请求 = (c_m >= MISSCMP)
一致请求 = (c_s >= SYNCED) AND NOT 失配请求
禁用请求 = 失配请求 AND (c_m >= BANNED) AND (BANNED >= MISSCMP)
```

配对无效，或 `MISSCMP<=0`、`SYNCED<=0` 时，三类请求均为 `false`；重新进入正常比较分支时，配对计数从初值重新开始。

连续计数用于确认偏差是否持续存在；相反结果会清零原方向计数，避免零散超差累计触发失配。

##### 通道状态综合与历史保持

每一路使用与自身有关的两组比较结果。例如，通道 1 使用配对 `(1,2)` 和 `(3,1)`。按表 38 形成该路状态。

**表 38  通道综合规则**

| 状态                      | 成立与保持条件                                                                                                            |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `isMissCompare`（失配） | 两组配对均有效时，两组都提出失配请求才成立；若仅一组有效，直接按该组的失配请求判定本通道失配状态；两组均无效时为`false` |
| `isSynced`（一致）      | 该路未失配、未禁用且至少一组配对有效时，任一组提出一致请求，或上一拍该路已一致，即为`true`；否则为 `false`            |
| `isBanned`（禁用）      | 两组都提出禁用请求，且`inAir=true`、`BANENABLE>0` 时置位；置位后锁存，数据恢复一致不自动清除                          |

一致状态与禁用历史初值均为 `false`，相关模型状态重新初始化时恢复初值。配对复位、返回地面或关闭禁用使能均不清除已有通道禁用锁存。`isSynced` 表示经过确认并可保持的数值一致性，本模块不进行时间戳对齐。

三路互相比较只能提供相对一致性证据。仅剩两路有效且互相失配时，两路均被标为失配，不能据此确定哪一路真实正确。

### 4.2 三通道数据表决

#### 4.2.1 设计目标与接口约定

本节的有效性、一致性、参与掩码及复位通知采用[第 1.1 节](#signal-state-terms)定义。三通道表决根据每路数据的有效性和一致状态，决定哪些通道参与计算，再按通道组合执行直通、平均或中值计算。无通道参与时，保持上次输出数值，并将输出标为无效。

对第 `i` 路，以 `x_i` 表示输入数值、`v_i` 表示有效性、`s_i` 表示一致状态。无一致合格通道时，应用可采用严格一致策略或允许唯一有效通道回退。`F` 控制三路全部参与时的计算方法，`data0` 用于历史数值初始化。通道顺序、资格策略及数值尺度由应用规定。

#### 4.2.2 参与资格与通道编码

先形成逐通道资格，再生成一致通道掩码；布尔量按 0 或 1 参与编码：

```text
q_i = v_i AND s_i
syncMask = q_1 + 2*q_2 + 4*q_3

若 syncMask 非零：
    h = syncMask
否则：
    严格一致策略：h = 0
    允许唯一有效通道回退：
        恰好一路 v_i=true 时，h = 该路位编码（1、2 或 4）
        其余情况，h = 0
```

`h` 为实际参与通道掩码，类型为 `uint8`；第 0、1、2 位分别表示通道 1、2、3。因此 `h=3` 表示第 1、2 路共同参与，`h=4` 表示仅第 3 路参与。

空速模型内展开的 Voter 通过 `SpCPT.CASVoterType`（下文简称 `mode`）选择策略：`mode=2` 为严格一致，其他值允许上述唯一有效通道回退；**没有针对 `mode=1` 的另一套主备选择分支**。操纵输入引用的库 Voter 固定包含唯一有效通道回退规则，不提供该 `mode` 配置。

参与掩码同时送入数值分支选择、输出有效性判定和参与集合变化检测。仅一路参与是掩码判定结果，不能与仅一路输入有效等同；一致状态及其历史由第 4.1 节的规则决定。

|     5 | `101` | 1、3     | `(x_1+x_3)/2`                                  |
|     6 | `110` | 2、3     | `(x_2+x_3)/2`                                  |
|     7 | `111` | 1、2、3  | `F>0` 时取 `(x_1+x_2+x_3)/3`，否则取三路中值 |
|     0 | `000` | 无       | 默认分支：上一拍表决数值                         |

当前编码正常范围为 0～7，显式计算分支覆盖 1～7，默认分支用于无通道参与。默认分支对应历史保持，不产生新的测量值。

记本拍表决值为 `z[k]`。当前分支结果直接输出，同时写入单拍历史，供下一拍作为 `z[k-1]` 使用。无通道参与时 `z[k]=z[k-1]`；历史初值为 `data0`，连续无通道参与时持续保持。历史延迟位于反馈支路，不使所有正常计算结果额外延迟一拍。

#### 4.2.4 输出有效性与参与集合变化

以 `v_out` 表示输出有效性、`r_out` 表示对外复位通知：

```text
v_out[k] = (h[k] > 0)
r_out[k] = v_out[k] AND (h[k] != h[k-1])
```

参与掩码历史初值为 `uint8(0)`，与数值历史分别保存。

**表 48  参与集合变化及输出行为**

| 本拍与历史条件                   | `v_out` | `r_out` | 数值动作           |
| -------------------------------- | --------- | --------- | ------------------ |
| 首次建立非零集合，或从零集合恢复 | `true`  | `true`  | 按本拍分支计算     |
| 非零集合变为另一非零集合         | `true`  | `true`  | 按新集合计算       |
| 非零集合保持不变                 | `true`  | `false` | 按本拍输入继续计算 |
| 本拍集合为零                     | `false` | `false` | 保持历史数值       |

复位通知表征有效参与集合的建立或变化，不回接清除数值历史。仅输入数值变化而集合不变时不产生通知；由非零集合变为零集合时也不产生通知。数值保持与输出无效同时成立，使用方须结合有效标志判断数据是否可用。

## 5 设备故障与冗余状态判定

### 5.1 处理目标与职责

本章说明如何根据输入有效性、设备状态及检查配置，形成设备故障状态和系统冗余丧失标志。处理包含两种规则：一是筛选配置指定的状态位并汇总，二是按故障条件及优先级确定输出代码。它们均按本拍输入进行组合判定，不包含第 3.1 节的连续异常确认、恢复等待或历史锁存。

位掩码仅承担表示和筛选作用，沿用第 1.4 节的约定。本章重点说明状态从何产生、哪些条件参与判断及结果如何输出。

### 5.2 按配置掩码判定冗余丧失

#### 判据与配置作用

将输入整理为本组状态位字 `F`，检查掩码记为 `M`，本组有效位范围记为 `R`，则：

```text
checkedBits = bitand(bitand(F, M), R)
LossRedundancy = (checkedBits > 0)
```

`M` 指定哪些状态位参与检查，`R` 排除本组范围外的位；只要被保留的任一位为 1，结果即为 `true`。这里不比较测量数值，也不计算剩余可用设备数量。关闭某个检查位只将该位排除在本次汇总之外，不清除原状态位，不改变前级测量数据的有效性。

#### VDT 状态输入的形成与使用

`Calc_PilotInData` 为每个 Current／Left／Right 通道检查 VDT 数组第 1、2、5、6 项，即 `CSSU_X、CSSU_Y、LSSU_X、LSSU_Y`。对任一通道 `c`：

```text
fault_c = NOT (CSSU_X.valid AND CSSU_Y.valid
               AND LSSU_X.valid AND LSSU_Y.valid)
```

按第 1.4 节约定，将三个 `fault_c` 分别写入 `VdtCBIT` 的 bit0、bit1、bit2，再送入 `Calc_SysInfo`：

```text
指定杆位的原始 valid
  → 各通道四项有效性汇总
  → VdtCBIT
  → 检查掩码与低三位范围筛选
  → VdtLossRedundancy
```

RSSU 两项、GPIO 及一致性／失配／表决结果不参与这条汇总路径。四项任一无效即可置位，不等待比较计数；该检查反映指定杆位记录的有效性，并非对该通道所有操纵输入的完整故障判断。

### 5.3 故障条件组合与状态编码

SCU 处理根据整体 `Valid` 及设备反馈 `INT_STS、EN_STS、STK_MON` 生成两种状态。以下代码均写入输出结构的 `data:uint8`。

```text

FaultStatus.data = 1，当 fault=true
FaultStatus.data = 0，当 fault=false
```

`ClawFaultStatus` 采用有优先级的分支。表内条件互斥；前项成立后不再由后项改变结果。

|      3 | `Valid=true`、`STK_MON!=0`，且（`INT_STS==0` 或 `EN_STS==0`） |                    2 |
|      4 | `Valid=true`、`STK_MON!=0`、`INT_STS!=0`、`EN_STS!=0`         |                    5 |

上述代码是分支选择结果，不是按位叠加的故障集合，不能按位掩码或数值大小推定其含义。当前模型可确定 1、2、5 的赋值条件，但其正式故障名称仍须接口定义确认。`FaultStatus` 与 `ClawFaultStatus` 使用的条件和代码不同，前者未单独检查 `STK_MON`，不能把两者视为同一个故障标志的重复输出。

两项均按 `tU8Data={data:判定代码, valid:true, reset:false}` 封装。**设备无效时，位置反馈可以无效，故障报告本身仍可有效。** 因此 SCU 的 `Valid=false` 会使 `Position.valid=false`，同时形成有效的 `FaultStatus=1`、`ClawFaultStatus=2`。该设计使下游可读取无效设备的判定结果，而无需把“报告有效”解释为“设备正常”。
