# VE25SP 模型设计说明

> 文档状态：设计草稿。2026-10-16 按“余度信号处理—下游数据整合”组织：先说明输入数据及状态如何形成，再按输出模块说明这些结果如何转为使用方接口。实现事实以当前 `sp` 模型、活动引用及字典为准；“当前配置”指核对的磁盘保存值。需求对应关系及静态核对边界见第四章。

## 1 总体设计与公共约定

SP 接收多种设备和采集通道的数据，先按各类输入的特点进行监测、选择或表决，再将这些处理结果组合为控制律、通信及显示所需的输出。前一阶段的共性集中在有效性和一致性判定；后一阶段的差异集中在使用哪些结果、怎样计算或保持，以及最终保留哪些信息。本文据此组织设计说明，使读者既能查阅共用算法，也能沿一个输出模块读完它的处理过程。

### 1.1 文档定位、实现范围及依据

本文解释当前 VE25SP 的实现设计，供模型理解、核对和维护使用。实现依据为 `sp` 中保存的模型、实际活动引用、库、字典及参数绑定；需求和接口文件用于追溯意图、比较规定行为及确认接口约定。文中的效果分析与待确认依据分别说明，不将需求文字或通用经验代替当前模型事实。

说明范围覆盖 `VE25SP` 根层的输入处理、下游输出生成及其活动模型引用，不展开下游控制律本身。必要的字段映射用于解释信息如何传递，完整字段、类型和维度仍查阅 [Bus 信号结构说明](VE25SP_Bus信号结构说明.md)。当前实现范围、来源版本和未运行的验证项目集中列在第四章。

### 1.2 两阶段职责、数据关系与阅读入口

第二章“余度信号处理”解释第一阶段如何从各设备或通道的记录形成可供使用的数据及状态。有效性主线决定数据能否接收、失效如何处理、恢复何时完成，以及从哪些候选中取数；一致性主线比较同一数据项的不同记录，形成逐路状态并确定表决通道。两条主线相互关联，设备故障与冗余判定另说明已有状态如何组合。

第三章“下游数据整合”按输出模块说明第一阶段结果的使用方式。同一模块中的资格检查、数值计算、指令历史、最终来源及接口装配放在一起，使输出条件能够从输入一路追踪。这里的整合包括计算、保持和状态形成；第二章也保留同阶段的单路监测及直接封装，不因标题突出余度处理而省略这些配套路径。

两阶段表示职责与数据依赖，不表示两个执行周期，也不意味着所有信号依次经过同一串行流程。第一阶段内部已有来源选择和混合空速表决；输出阶段还会按本项用途再次选择来源。实际依赖如下。

**表 1  算法之间的数据与控制关系**

| 处理路径           | 输入与前级处理                                      | 算法配合                                                                                 | 输出及后续用途                                                                          |
| ------------------ | --------------------------------------------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| ADAHRU 数据处理    | 三路同类数据及各自有效性                            | 三通道一致性监控形成逐路状态；其后并行执行来源选择与空速表决                             | 来源选择形成导航数据和诊断状态；空速表决结果单独写入导航总线                            |
| FTADC 数据处理     | 单套设备的整体有效性、分项数据及分项有效性          | 每项独立执行异常确认、恢复确认和数值保持                                                 | 形成 FTADC 分项结果；其中空速继续进入混合来源表决                                       |
| 混合来源空速处理   | FTADC 处理后的空速及 ADAHRU 第 1、2 路空速          | 统一数值尺度后重新执行一致性监控，再按新形成的通道状态表决                               | 将融合结果写入`ftadcVoterCAS_mps`，保留原 FTADC 分项结果                              |
| 操纵输入处理       | 每项 VDT／GPIO 的 Current、Left、Right 数据及有效性 | 分项一致性监控后进行数值表决；没有有效且一致通道时，仅在恰好一路输入有效的情况下采用该路 | 输出操纵数据及有效性、复位通知，逐路比较状态不随最终数据输出                            |
| MPIO、MCU 数据处理 | 整体有效性及分项反馈                                | 指定数值采用异常确认与保持；MPIO 的 24 项业务字段及 MCU 的 FaultLevel／WorkMode 直接封装 | 输出各项数据及有效性；当前外围 reset 固定为 false                                       |
| 地面站消息处理     | 三个候选位置，各含两组消息及有效性                  | 按 FCC 身份确定优先位置，两组分别选源并提取业务项                                        | RemotePilot 输出来源变化通知，RemoteFMCP 抑制通知                                       |
| 设备故障与冗余判定 | 原始有效性、设备状态和检查掩码                      | 汇总指定状态位；或按条件优先级输出故障代码                                               | 形成 Sys 冗余丧失标志、SCU 故障报告                                                     |
| 运行状态控制       | 外部 VTOL 运行状态                                  | 分类为地面／飞行处理策略                                                                 | 影响 ADAHRU 最高等级并列时、RA 两路均有效时的来源保持，以及混合来源比较中的新增禁用许可 |
| 导航控制律输入 | 前级导航结果、FTADC 压力与 ADAHRU 温度记录 | 合成状态、转换数值、计算高度和真空速，最后按配置确定各项输出 | 形成导航数值及有效性／通知；计算日志独立保留 |
| 操纵指令形成 | GCS、飞行员表决记录及 MPIO 检查状态 | 数值转换与资格判定并行；开关变化形成事件，条件更新形成保持型指令 | 两支路分别形成操纵消息，再按配置选择最终输出 |
| FMS 与设备反馈输出 | MPIO 和 MCU／SCU 处理记录 | 按字段执行条件更新、替代码输出、直接提取或位置标定 | 形成重量、重心和设备接口结果 |
| 系统就绪形成与汇总 | 最终导航有效性、设备冗余及预检条件；三机已报告状态 | 本机条件生成与报告汇总分开执行，连续确认只用于指定检查 | 本机 CCDL 报告和独立汇总结果分别输出 |


操纵输出模块并行形成地面站与飞行员消息，再按配置确定最终操纵输入及空地结果。空地值与有效性送入导航输出；两条操纵支路的数值还分别送往显示，显示并非只转发最终选中支路。导航输出的最终有效性参与 CCDL 的数据组检查，同时供 DRMS 输出使用。

CCDL 形成本机就绪／限制派遣报告；另一条独立路径读取 `SysInfoData` 中三机已报告的状态并汇总，汇总就绪送往 SYS 和显示，汇总限制派遣送往显示。本机本拍新报告没有在本模块内直接回接形成该汇总。FMS 则独立使用 MPIO 记录形成输出。

按算法查阅时，可从第二章两条主线进入；按输出接口查阅时，第三章各模块给出完整处理关系。跨方法的输出差异及模块位置集中列在附录 A，避免在概念尚未建立时提前混用不同处理层的规则。

### 1.3 信号状态、来源身份及信息保留约定

输入有效性、监测状态、选用结果和输出通知回答不同问题。以下先统一这些术语，再说明来源身份如何保留，以及状态怎样进入输出。相同字段名不意味着所有处理路径采用相同判据。

<a id="signal-state-terms"></a>

#### 1.3.1 术语定义与使用约定

本节统一后续算法章节使用的状态术语；数据来源与通道身份另见[第 1.3.2 节](#channel-identity)。**有效性、一致性、异常状态和选用结果分别回答不同问题，不能合并为一个互斥的“正常／异常”状态。** 同名 `valid` 在不同处理环节可能采用不同判据，正文中须说明其来源及使用条件。输入有效性、异常监测的接收许可和最终输出有效性，是相对于当前环节的定义，不构成所有信号必经的固定等级。

**表 2  信号状态与监测术语**

| 术语／标记                              | 定义                                                                                       | 使用边界                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 输入有效性`valid/Valid`               | 上游报告的数据或消息可用性；异常监测中以`g` 表示整体有效性，以 `d` 表示分项有效性      | 是本级算法的输入，不直接代表已通过本地比较或异常恢复确认                               |
| 输出有效性`validOut` 或输出 `valid` | 当前处理环节按自身使用规则形成的可用标志                                                   | 异常监测表示允许接收；表决表示存在参与通道；来源选择采用所选数据或消息组的有效性       |
| 一致性`isSynced`                      | 数据与其他有效通道经过比较和连续确认后形成的数值一致状态，包含规定的历史保持               | 是相对于比较对象的判断，不表示时间戳同步；更换比较组合须重新评价                       |
| 配对失配／通道失配`isMissCompare`     | 配对失配表示两路持续超差；通道失配由与该路有关的配对结果综合形成                           | 与某一路配对失配，不必然使该通道被判为失配                                             |
| 异常状态`B/isAbnormal`                | `AbnormalMonitor` 根据分项无效的持续过程及恢复历史形成的状态                             | 不等于原始`valid` 取反；该算法不自行检查数值范围或多源差值                           |
| 禁用状态`isBanned`                    | 满足禁用条件后锁存的通道排除状态                                                           | 禁用使能关闭不清除已有锁存；本版所列一致性实例均关闭新增禁用                           |
| 来源编号                                | 指定从哪一路读取数据，例如`adahruSrc、RaSrc`                                             | 编号非零只表示确定了来源，各项数据是否可用仍看输出有效性                               |
| 参与通道掩码`chUsed`                  | 按位记录一个或多个实际参与表决的通道                                                       | 三路按 1、2、4 编码；与来源编号不是同一种编码，诊断`ChannelUsed` 应结合处理类型解释  |
| 复位通知`reset`                       | 按应用规则通知数据首次有效、恢复有效、来源变化或参与表决的通道变化；部分应用也通知失去来源 | 是事件通知，不是健康等级，也不表示清除本模块全部内部状态；触发条件及是否输出由应用确定 |
| 历史数值保持                            | 不接收新数值时继续输出先前保存的数值                                                       | 保留数值不表示当前有效；输出无效是否保持数值，须依据具体算法判断                       |
| 设备故障状态                            | 设备上报或由设备状态组合形成的故障信息，如 MCU 故障等级、SCU 故障代码                      | 与比较失配、监测器内部异常状态分开定义；报告有效不代表设备正常                         |
| 冗余丧失标志`LossRedundancy`          | 按检查配置对指定状态位汇总得到的布尔结果                                                   | 当前掩码算法不直接计算剩余设备数量；结果为假也可能是检查位被屏蔽                       |
| 操作事件与指令状态 | 操作事件报告满足条件的输入变化；指令状态按规定条件更新并可持续保持 | 事件可形成一拍或延长脉冲；保持的指令值不能证明当前原始输入仍有效，见第 3.2 节 |
| 系统就绪 | 根据规定检查和状态条件形成的本机报告或多机汇总结果 | 与单项数据有效性不同；本机生成与接收报告汇总采用不同输入，见第 3.4 节 |

后续章节沿用上述术语，并在各算法入口定义局部符号。本文以“拍”表示相应算法的一次执行；计数门限与实际时间之间的关系须结合各自计数结构和调度确认。

<a id="channel-identity"></a>

#### 1.3.2 数据来源与通道身份

输入记录除数值及有效性外，还通过端口名称、总线成员或数组位置区分来源。`Curr/Current、Left、Right` 属于这种**结构中约定的通道身份**，用于区分同一数据项的不同候选记录；它们不是有效性或故障状态，也不一定以独立的身份字段随每项数据传递。

**表 3  数据身份的含义与边界**

| 身份信息                              | 含义                                                                                          | 使用边界                                                                         |
| ------------------------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 相对通道`Curr/Current、Left、Right` | 本机视角下的当前、左、右逻辑通道位置；`Curr` 常用于端口后缀，`Current` 常用于内部总线成员 | 不直接表示飞机安装位置、左／右操纵杆，也不能按名称固定等同于 FCC1／FCC2／FCC3    |
| FCC 编号`fccId、activeFccId`        | GCS 选源使用的本机编号及主控 FCC 身份                                                         | 通过映射确定优先输入位置；两字段编码不同，不能把编号值直接当作输入序号或参与掩码 |
| 测量设备或协议源节点身份              | 标识原始测量设备或报文发送节点，例如 ADAHRU、RA 的设备源号和地面站协议的消息源节点            | 与接收、采集或转发通道属于不同维度；多份候选记录不等于多个独立物理信息源         |

**各处理链保留身份的阶段不同。** 输入按通道区分，不代表最终数值输出仍携带全部原通道信息。

**表 4  通道身份的处理与保留**

| 数据类别         | 输入组织与本地处理                                                                                                                                                   | 输出中的身份信息                                                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 飞行员杆位、按键 | `VDT_Stick_Curr/Left/Right`、`Dis_Key_Curr/Left/Right` 各含同构业务字段；同一项按 `Current、Left、Right` 顺序组成三路，进行比较与表决                          | `VDT`、`GPIO` 输出按业务项保留 `data/valid/reset`；逐路身份及表决参与掩码不附在最终数据中                                                                                    |
| 地面站操纵信息   | `SpIn_Gcs_Curr/Left/Right` 是三份候选记录；`RemotePilotCtrl` 与 `RemoteFMCP` 按各自有效性和优先输入位置分别选源，不作三路业务数值比较                          | `GcsData` 保留选定业务数据及其有效性、复位信息；两组选源的内部 `voterState` 均被终止，来源诊断不随该总线输出                                                                   |
| 系统状态         | `Sys_Status_Curr/Left/Right` 以 `SpIn_CcdlMsg` 输入，经 `Calc_SysInfo` 按各路 `Valid` 分别处理就绪状态和限制派遣信息；`SpIn_SysInfo_Curr` 是另一路本机输入 | 中间总线`SysInfoData` 保留 `Current/Left/RightSysReady` 及 `Current/Left/RightLimitDispatchInfo`；后续汇总为 `SysReady/LimitDispatch`，控制律 SYS 接口不保留这六个分路字段 |
| 导航测量         | ADAHRU 的同类数据以三元素数组组织，RA 高度以两元素数组组织                                                                                                           | 候选下标用于区分设备数据，选用来源及诊断另行封装；设备源号到模型数组下标的上游适配关系须另核对                                                                                     |

例如，`VDT_Stick_Curr.CSSU_X` 与 `VDT_Stick_Left.CSSU_X` 是同一杆位量在两个逻辑通道中的记录；`CSSU_X`、`RSSU_X`、`LSSU_X` 才用于区分不同操纵装置的业务项。不能将外层 `Left` 与内层 `LSSU` 混为一义。表决后的操纵数据项仍通过数组位置区分，并由控制律接口转换为相应字段；不再保留的是同一项的三路候选结构。

GCS 中可以直接确认 FCC 身份到候选位置的映射。例如，`fccId=0` 且 `activeFccId=PFCC2` 时，优先位置为 `Right`；对两组消息分别选源时，只有对应消息组的 `Right` 输入有效才选用它。该映射说明选源控制如何定位输入，不证明地面站指令由 FCC2 产生，也不能直接推广为 VDT 或 Sys 输入的物理接线表。GCS 的位置号 `1/2/3` 与第 1.3.1 节的参与掩码 `1/2/4` 须分别解释。

接口采集与传递的依据集中列于第 1.3.5 节。相对通道到实际 FCC、通信路径及输入填充的完整对应仍需核对上游适配与接线；本文保留这一适用边界。

#### 1.3.3 状态关系与输出保留

状态能否同时成立，应在同一数据、同一处理环节下判断。表 5 给出本版实现中的典型关系，接收与恢复条件在第 2.1 节说明，比较状态及表决资格在第 2.2 节说明。

**表 5  状态共存与互斥关系**

| 条件或场景                                                           | 可以同时出现的状态                                                                              | 后续影响                                                               |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| ADAHRU 某路 CAS 失配已经确认，上游仍报告有效                         | 输入`valid=true`、`isMissCompare=true`、`isSynced=false`                                  | 预处理保留原始有效性；空速表决在保存配置 `CASVoterType=2` 下排除该路 |
| 仅一路有效，缺少有效比较对象                                         | 输入`valid=true`、`isSynced=false`、`isMissCompare=false`                                 | 无一致性支持不等于已确认失配；是否允许单路使用由表决策略决定           |
| FTADC CAS 整体持续有效，异常已确认，分项有效性恢复但恢复计数未达门限 | 输入 CAS 分项`valid=true`、内部 `B=true`、输出 `valid=false`                              | 继续保持历史数值，等待恢复确认                                         |
| FTADC CAS 整体有效、此前无异常，分项刚出现无效且异常计数尚未达门限   | 输入 CAS 分项`valid=false`、内部 `B=false`、输出 `valid=false`                            | 保持 FTADC CAS 的历史数值，尚未确认异常                                |
| 同一`CmpMonitor` 通道输出                                          | `isSynced=true` 要求本路有效且未失配、未禁用                                                  | 该路一致状态不能与通道失配或禁用状态同时为真                           |
| SCU 整体输入无效                                                     | `Position.valid=false`；故障报告的 `FaultStatus.valid=true`、`ClawFaultStatus.valid=true` | 位置不可用与故障报告可用可以同时成立，代码判据见第 2.3.2 节              |

监测及选用信息形成后，可能附在数据记录中、另行写入诊断总线，或只供模块内部使用。表 6 将输入信息、本级处理和输出保留位置对应起来；各环节的连接关系见第 1.2 节。

#### 1.3.4 状态字与位掩码约定

位编码是记录多个布尔条件的表示方式，具体判定仍由表决、故障检测或配置规则完成。通道位掩码按位权 1、2、4 表示三路，某位为 1 的含义须由变量定义；相同数值不能跨变量解释为相同状态。

**表 7  位掩码的用途与解释**

| 变量                         | 位为 1 的含义                                          | 产生与使用                                               |
| ---------------------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| `chUsed`                   | 对应通道实际参与表决                                   | 第 2.2 节根据有效性与一致性确定；可同时置多个通道位      |
| `VdtCBIT`                  | 对应 Current／Left／Right 通道的指定杆位有效性检查失败 | 第 2.3.1 节说明检查对象；用于冗余状态判定                  |
| `check_VDT_Bit` 等检查掩码 | 允许对应状态位参与本次汇总                             | 配置输入；屏蔽检查位不清除原状态位                       |
| 选源诊断`ChannelUsed`      | 编码所选来源                                           | 本文单源应用采用 1／2／4；是否受有效性约束由具体实现决定 |

例如，在操纵输入应用中，数值 2 对 `chUsed` 表示选用 Left，对 `VdtCBIT` 表示 Left 检查失败，对 `check_VDT_Bit` 表示仅检查 Left。以下 `stateBits` 则按不同状态属性分配位号，须与通道位掩码分开解释。

##### 一致性诊断状态字

`tSignalState` 包含 `lastTimestamp` 和 `stateBits`。在 ADAHRU／RA 当前使用的 `Calc_SignalState` 及双精度封装中，`lastTimestamp` 固定为 0，状态字实际按下式形成：

```text
stateBits = valid + 2×isSynced + 4×isMissCompare + 8×isBanned
```

该表达式说明上述封装的实际写入，不作为所有 `tSignalState` 使用位置的统一位定义。当前模型与字典注释存在以下差异：

**表 8  当前一致性封装与字典注释的差异**

| 位号（从 0 开始） | 一致性封装实际写入 | `SP_State.sldd` 字段注释                |
| ----------------: | ------------------ | ----------------------------------------- |
|                 0 | `valid`          | `valid`                                 |
|                 1 | `isSynced`       | `updated`                               |
|                 2 | `isMissCompare`  | `isTimeout`                             |
|                 3 | `isBanned`       | `isAbnormal`                            |

<a id="public-runtime-control"></a>

### 公共控制条件：运行状态分类及其策略作用

同等条件的多个来源如何取舍，与当前采用地面还是飞行处理策略有关。模型先将输入 VTOL 状态归为地面类或飞行类，再将分类结果用于导航来源保持和混合空速比较的新增禁用许可。以下从状态映射说明分类如何形成，再结合下游分支说明分类结果如何影响处理。

#### 分类机制

运行状态分类用于决定同等选源条件下采用固定优先顺序还是保留历史来源，并为混合空速比较提供新增禁用的空地条件。输入 `vtolState` 属于 Unknown、Disarm、Arm、MtrCheck、SurfCheck 中任一状态时，输出 `OnGnd=true`，采用地面策略；其余已定义状态输出 `OnGnd=false`，采用飞行策略。下游需要飞行标志时，取 `inAir=NOT OnGnd`。

分类以本拍接收状态计算，不含本地锁存、延迟或连续确认。同类状态之间变化不改变分类结果；跨类别变化在本次分类计算中产生新结果。分类模块不负责外部状态的进入／退出判定，也不以该映射独立检测物理离地。

### 2.1 有效性处理与数据来源选择

本节围绕输入有效性依次解释接收、恢复和候选选用。即时处理直接使用本拍有效标志；连续异常监测还保存计数和异常历史；来源选择则在多份候选中按资格、优先关系及适用历史确定读取对象。它们可以按输入需要分别使用，不能把异常确认当成所有选源的必经步骤。涉及的地面／飞行条件采用本章[公共控制条件](#public-runtime-control)。

#### 2.1.1 有效性处理的方式

输入失效后，需要分别规定输出数值如何处理、输出是否有效，以及恢复后何时重新接收。本节采用[第 1.3.1 节](#signal-state-terms)的整体／分项有效性、异常状态和历史数值定义，先说明即时输出与连续异常监测，再说明前级接口应用及候选来源选择；使用方增加的资格检查和状态合成在第三章对应模块说明。

即时处理根据本次输入有效性直接封装或控制输出，用于无需连续异常历史的接口；连续异常监测在当前有效性之外保存计数和异常历史，用于确认持续失效，并限制已确认异常后的恢复接收。两类方式分别用于不同数据，应用可以直接选用所需规则。

这些机制先解决本项数据能否更新及持续异常后何时恢复。候选来源选择随后解释从哪份记录取数；下游仍可能增加业务资格或独立数值历史，不能将本级有效性直接当成全部输出接口的使用条件。

#### 2.1.2 即时有效性处理的输出规则

即时处理依据当前输入的有效标志直接确定输出，不累计异常或恢复计数。数值记录可以继续传递本拍值，同时将有效标志写入输出；业务状态则按接口规则处理，例如消息无效时将本路就绪标志置为假，或将限制派遣信息替换为默认代码。表 12 将这些处理与具体接口对应。

#### 2.1.3 连续确认与异常状态

连续异常监测分别确定本项输出是否有效、何时确认或清除异常，以及输出数值是否接收新值。整体或分项输入无效时，本项输出被标记为无效，数值保持上一拍结果。整体持续有效时，分项连续无效的计数用于确认异常；异常确认后，分项连续有效的计数用于确认恢复。当前有效标志与异常历史共同决定本项数据能否重新接收。

##### 输入与配置

输入量包括整体有效性 `g`、分项有效性 `d`、当前数值 `dataIn` 和历史数值初值 `data0`。配置量 `A` 为异常确认门限，`R` 为已确认异常后的恢复门限。库输出包括异常状态 `B`、处理后有效标志 `validOut` 和数值。`validOut=true` 时接收并更新数值，否则保持历史数值；后文将这一更新条件称为接收许可。

异常判定依据有效标志及其历史；输入数值仅用于更新与保持，不在本算法内进行物理量范围或多源差值检查。

**表 13  异常监控的配置作用**

| 配置量    | 控制作用与边界                                                                  |
| --------- | ------------------------------------------------------------------------------- |
| `A`     | 连续异常计数的确认门限；`A<=0` 时关闭异常状态判定，接收许可仍要求 `g AND d` |
| `R`     | 异常历史的恢复确认门限；`R<=0` 时取消恢复等待，异常置位条件仍单独生效         |
| `data0` | 尚未接收数据时使用的数值历史初值，不决定输出有效性                              |

##### 连续条件计数

为分别识别连续失效和有效恢复，设置两个独立计数器，输出分别为异常计数 `errorCnt` 和恢复计数 `resumeCnt`。

**表 14  连续计数的累积与清零条件**

| 计数输出      | 累积条件               | 清零条件               | 输出限幅范围      |
| ------------- | ---------------------- | ---------------------- | ----------------- |
| `errorCnt`  | `g=true AND d=false` | `g=false OR d=true`  | `0 ～ max(A,0)` |
| `resumeCnt` | `g=true AND d=true`  | `g=false OR d=false` | `0 ～ max(R,0)` |

每条计数链采用单拍 Delay 存储历史值，初值为 0；Delay 输出经动态限幅后形成计数输出，同时加 1 反馈至 Delay 输入。Delay 的外部复位方式为 `Level hold`，表 14 的清零条件成立时复位到初值。条件中断即清零，使判定依据保持为连续过程，零散出现的无效或有效状态不会累计形成确认。

限幅上限使用 `max(门限,0)`，保证上限不低于下限 0；门限为负时，上下限均为 0。该非负限幅与异常状态中的 `A>0` 使能判断分别承担数值约束和功能使能的职责。

##### 异常状态与输出有效性判定

整体有效且异常判定开启时，分项连续无效达到异常门限才确认异常；恢复门限大于零时，已经确认的异常需要分项连续有效达到恢复门限才清除。整体无效或 `A<=0` 时，本拍异常状态直接为假，不继续保留原异常；`R<=0` 时不等待恢复计数，但本拍异常确认条件仍生效。

输出有效性同时要求整体有效、分项有效且当前没有异常。因此，分项刚变为无效时，输出立即标为无效并保持历史数值；异常计数尚未达到门限，只表示还没有确认持续异常，并不允许继续接收该无效输入。整体持续有效且恢复门限大于零时，已确认异常的数据即使恢复了分项有效标志，也须完成恢复确认后才能接收。

异常历史初值为 `false`。以 `B`、`B_prev` 分别表示本拍和上一拍异常状态，上述规则在模型中表示为：

```text
B = g AND (A > 0)
    AND ((errorCnt >= A)
         OR (B_prev AND NOT(resumeCnt >= R)))

validOut = g AND d AND NOT B
```

式中的恢复条件只取消异常历史的保持；整体有效且 `A>0` 时，只要本拍异常确认条件成立，仍置位异常。在 `A>0、R>0` 且按表 14 更新计数时，两类计数的累积条件互斥，不会同时达到各自的正门限。

##### 异常状态与数值处理对照

表 15 在 `A>0、R>0` 条件下，对照输入有效标志及上一拍异常状态，列出本拍异常状态、输出有效性和数值动作。前述逻辑产生 `B` 和 `validOut`，第 2.1.4 节的数值保持环节根据 `validOut` 选择接收当前输入值或保持上一拍输出。

**表 15  异常状态、接收许可与数值处理**

| 输入及历史条件                                       | 当前异常状态`B` | `validOut` | 数值动作     |
| ---------------------------------------------------- | ----------------- | -----------: | ------------ |
| 整体`g=false`                                      | 清除；两计数复位  |    `false` | 保持历史数值 |
| `g=true、d=false`，此前无异常且异常计数未达 `A`  | 尚未确认异常      |    `false` | 保持历史数值 |
| `g=true、d=false`，异常计数达到 `A` 或此前已异常 | 置位或保持异常    |    `false` | 保持历史数值 |
| `g=true、d=true`，此前无异常                       | 正常              |     `true` | 接收当前数值 |
| `g=true、d=true`，此前已异常且恢复计数未达 `R`   | 保持异常          |    `false` | 保持历史数值 |
| `g=true、d=true`，此前已异常且恢复计数达到 `R`   | 清除异常          |     `true` | 接收当前数值 |

在 `A>0、R>0` 且整体持续有效时，分项恢复有效后的处理取决于此前是否已确认异常：尚未确认异常时可直接接收；已确认异常时，须连续有效至恢复计数达到 `R`，才清除异常并重新接收。恢复确认期间，分项再次无效会清零恢复计数，异常状态继续保持，下次恢复重新计数。启动后若分项持续无效已被确认异常，首次恢复有效也按上述恢复确认规则处理。整体失效会清除计数和异常历史，其后恢复时的接收规则见第 2.1.4 节。

正门限配置下，增大 `A` 会延后异常确认，但不会使无效输入继续更新输出数值；增大 `R` 会延长整体持续有效时、已确认异常后的恢复等待。

#### 2.1.4 数值保持与有效性恢复通知

##### 数值更新与保持

数值保持用于在数据不可接收时保留已有输出，恢复接收后再使用当前输入。根据第 2.1.3 节形成的 `validOut`，选择当前输入或上一拍输出；选择结果对外输出，并写回数值历史：

```text
validOut=true  ：dataOut = 当前 dataIn
validOut=false ：dataOut = 上一拍 dataOut
```

数值历史初值为应用提供的 `data0`。尚未接收有效数据时输出该初值；接收过有效数据后，无效期间保留末次接收值。输出有效性同样取 `validOut`，因此保持历史数值时，输出仍标记为无效。

整体失效会清除计数和异常状态；数值保持环节没有外部复位端口，仍保留数值历史。整体与分项随后均有效时，可直接接收当前输入。

##### 有效性恢复通知

恢复通知通过 `reset` 字段报告本项输出首次有效或由无效恢复有效，使使用方能够区分这一变化与持续有效状态。采用该通知的应用保存上一拍 `validOut`，初值为 `false`，与本拍值比较：

```text
reset = 当前 validOut AND NOT 上一拍 validOut
```

`validOut` 从假变真时，`reset` 为真一个执行拍；持续有效或本拍无效时为假。该规则适用于首次有效及无效后的恢复，不要求数值发生变化。

FTADC 在监测器外围生成并封装该通知，见第 2.1.5 节。`AbnormalMonitor` 输出数值、有效性及异常状态，不输出 `reset`。通知只随数据输出，不反馈清除监测器内部状态；计数清零和异常状态清除仍由第 2.1.3 节的条件决定。

#### 2.1.5 FTADC 应用与调用配置

##### 处理关系与实例组织

FTADC 的压力、迎角、侧滑角和空速分别执行异常监测，各项共用设备整体有效性，独立保存分项异常及数值历史。外围检测各项处理后有效性由假变真的事件，形成恢复通知，再将五项结果写入导航数据总线；其中空速还将进入后级混合来源表决。

#### 2.1.8 来源选择的处理关系

数据来源选择用于从多份候选记录中确定一份供后续使用。来源判定先评价候选数据，并结合优先关系及适用的历史来源规则决定本拍来源；随后读取该来源的数据，形成有效性、变化通知和诊断输出。来源判定与输出有效性分别处理。应用决定是否输出来源信息；保留来源信息时，下游可结合有效标志解释所选数据。

处理关系为：**来源判定 → 数据提取 → 有效性与变化通知 → 输出封装**。先明确各应用的来源判定差异，再解释来源确定后的共用输出机制，能够把换源条件与最终数值、状态对应起来。来源编号和单路掩码的含义沿用第 1.3.1 节，各应用按自身编码解释。

ADAHRU 和 RA 通过 `SignalProcessingLib/SrcSelect` 逐项提取数据；GCS 选择整组消息后拆分业务字段。设备分级、公共来源与 CAS 专用来源属于 ADAHRU 的判定方式，地面站的身份映射及两组独立有效性则属于 GCS 的判定方式。

#### 2.1.9 来源判定与应用差异

| ------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------ | -------------------------------------------------------- | ----------------------------------------------- |

#### 2.1.10 数据提取、复位与诊断封装

来源判定先给出从哪一路读取数据，逐项输出随后决定怎样传递该路数值、有效性和诊断。ADAHRU、RA 共用 `SrcSelect` 完成这一步；来源编号由外围判定提供，`SrcSelect` 不负责统一决定来源。GCS 的整组数据选择和通知采用第 2.1.13 节所述规则。

来源判定得到编号 `index` 后，逐项选择器读取该通道本拍的 `data` 和 `valid`。选择器不对多路数值求平均，也不在输入无效时保持历史数值；即使来源编号继续沿用，读取的仍是所选通道本拍的数值。

记本拍来源编号为 `index[k]`，有效来源编号为 `e[k]`：

```text
e[k] = index[k]，当所选数据 valid=true
e[k] = 0，       当所选数据 valid=false

reset[k] = valid[k] AND (e[k] != e[k-1])
```

有效来源历史初值为 0。首次有效、切换到另一有效来源及无效后恢复有效时均产生复位通知；持续有效且来源不变、或本拍无效时不产生通知。即使来源编号未变，有效性恢复仍会触发。各数据项分别保存有效来源编号，依据该编号的变化及本拍有效性生成复位通知。

来源判定保存的“上一拍来源”用于决定本拍是否换源；此处保存的“上一拍有效来源”用于生成复位通知。前者可以在数据无效时保留原编号，后者在本拍数据无效时记为 0，因此能够识别同一路数据失效后的恢复。

选定数值及 `valid/reset` 由调用模块封装为数据输出。调用模块另根据来源编号生成 `voterState`，通过 `SrcSelect` 的第三输入传入；`SrcSelect` 将其与三路输入 `state` 组成诊断输出。当前两类应用均填写 `VoterType=SourceSelect`，并将来源编号 1、2、3 编码为 1、2、4：

```text
tRedundantDataState
├─ ch1SignalState : tSignalState，保留第 1 路输入 state
├─ ch2SignalState : tSignalState，保留第 2 路输入 state
├─ ch3SignalState : tSignalState，保留第 3 路输入 state
└─ voterState     : tVoterState
   ├─ VoterType   : Enum_VoterType，填写 SourceSelect
   └─ ChannelUsed: uint8，按来源编号 1、2、3 编码为 1、2、4
```

来源编号 1、2、3 与诊断编码 1、2、4 分别表示同一组通道，但编码方式不同。`ChannelUsed` 不受输出 `valid` 门控，非零只表示已选定来源，不能据此判定数据有效。该单源编码也不能直接替代第 2.2 节表决中的多通道参与掩码。

#### 2.1.11 ADAHRU 导航数据选源

##### 2.1.11.1 输入数据与处理关系

本应用先评价三台设备的数据有效性，再确定公共来源和 CAS 专用来源，最终输出选定数据、诊断状态、设备等级及公共来源编号。

输入为 `adahruNormalInfos:BUS_adahruNormalInfos` 和地面／飞行分类 `OnGnd`。输入包含 31 类信号，每类均为三路数组，各路携带 `data`、`valid`、`isSynced` 和 `state`。组合纬度、经度使用 `Bus_DoubleSignalNormalInfo[3]`，其余 29 类使用 `Bus_SingleSignalNormalInfo[3]`。

**公共来源**是除 CAS 外其余 30 类导航数据共同采用的设备来源。**CAS 专用来源**是单独选定的空速来源：优先使用公共来源的空速；该路空速无效时，再从其他设备中选择有效空速。两种来源分别送入对应的数据选择器。

##### 2.1.11.2 设备有效性评价

对每台设备，先按表 24 检查惯性、速度／航向和位置数据是否有效，再按表 25 给出 1～4 级的设备有效性等级。等级越高，选源优先级越高。所有条件仅读取相应信号的 `valid`，不读取 `isSynced` 或 `stateBits`，CAS 也不参与设备等级计算。

**表 24  设备有效性条件**

| 条件                  | 成立要求                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------- |
| 惯性条件`C_I`       | `Pitch`、`Roll`、`SforX`、`SforY`、`SforZ`、`Q`、`P`、`R` 全部有效                            |
| 速度／航向条件`C_N` | `NorthVelocity`、`EastVelocity`、`TrueHeaading` 全部有效，且 `GpsAltRate`、`AdAltRate` 至少一项有效 |
| 位置条件`C_P`       | `GpsHeight`、`CombLate`、`CombLong` 全部有效                                                            |

`GpsAltRate` 与 `AdAltRate` 的“至少一项有效”针对同一设备内的两种高度变化率。`TrueHeaading` 为模型字段的实际拼写。

**表 25  设备等级判定**

| 等级`W` | 条件                        | 具备的有效数据组                                 |
| --------: | --------------------------- | ------------------------------------------------ |
|         4 | `C_I AND C_N AND C_P`     | 惯性、速度／航向、位置均完整                     |
|         3 | `C_I AND C_N AND NOT C_P` | 惯性与速度／航向完整，位置不完整                 |
|         2 | `C_I AND NOT C_N`         | 惯性完整，速度／航向不完整；位置条件不影响该等级 |
|         1 | `NOT C_I`                 | 惯性不完整；其余条件不提高该等级                 |

三台设备的等级形成 `AdahruWeight=[W_1,W_2,W_3]`，类型为 `uint8[3]`。接口中的 `Weight` 表示设备有效性等级，用于决定优先选用哪台设备，不参与数值加权计算。

该分级依次以惯性、速度／航向和位置数据的完整性提高等级。因此，某项数据失效是否引起换源，取决于它是否改变设备等级以及三路等级的相对关系。

##### 2.1.11.3 公共来源选择

先比较三台设备的等级，选择等级最高的设备。多台设备等级相同时，根据 `OnGnd` 决定采用固定顺序，还是继续使用上一拍选中的设备：

**表 26  公共来源选择规则**

| 条件                                                | 选择规则                                |
| --------------------------------------------------- | --------------------------------------- |
| `OnGnd=true`                                      | 在最高等级设备中按第 1、2、3 路顺序选择 |
| `OnGnd=false`，上一拍来源仍具有最高等级           | 保持上一拍来源                          |
| `OnGnd=false`，上一拍来源不具有最高等级或尚未建立 | 在最高等级设备中按第 1、2、3 路顺序选择 |

选择结果 `adahruSrc` 为 `uint8` 标量，取值 1、2、3 分别表示三台设备。该编号通过一个单拍延迟保存为 `lastSelect`，初值为 0。首次执行时，选择等级最高且编号最小的设备；本模块没有额外的换源连续确认计数。

三路均为等级 1 时仍按上述规则选出来源：地面选择第 1 路，飞行时保留上一拍已建立的来源，首次选择第 1 路。因此，`adahruSrc` 非零只表示已确定来源，各项数据是否可用仍须依据其输出 `valid`。

因此，飞行中另一台同等级设备恢复有效时，可以继续使用当前设备；另一台设备的等级更高时，则切换到等级更高的设备。

##### 2.1.11.4 CAS 专用来源选择

设备等级计算不包含 CAS，因此等级最高的设备也可能没有有效空速。空速来源优先与公共来源保持一致；公共来源的 CAS 无效时，再按第 1、2、3 路顺序查找有效空速。`CAS_Select` 按以下顺序确定本拍 CAS 来源编号：

```text
如果公共来源的 CAS 有效：
    CAS 来源编号 = 公共来源编号
否则，如果第 1 路 CAS 有效：
    CAS 来源编号 = 1
否则，如果第 2 路 CAS 有效：
    CAS 来源编号 = 2
否则，如果第 3 路 CAS 有效：
    CAS 来源编号 = 3
否则：
    CAS 来源编号 = 上一拍 CAS 来源编号
```

来源编号 1、2、3 分别对应三台设备。每拍选择结果通过单拍延迟保存，供下一拍三路 CAS 均无效时继续使用；历史初值为 1，因此首次执行且三路 CAS 均无效时，来源编号为 1。

这里仅以 `CAS.valid` 为选择条件，不要求 `CAS.isSynced=true`。因此，单源 CAS 可与独立空速表决采用不同通道，CAS 来源也可与其他导航数据的公共来源不同。

三路空速均无效时，只保留原来的**来源编号**。后级仍读取该设备本拍的 `data`，并输出 `valid=false`。这里不保持上一拍有效空速；第 2.2 节表决在没有通道参与时才保持历史数值。

##### 2.1.11.5 选定数据与诊断输出

公共来源编号送入 30 类导航数据的选择器，CAS 专用编号送入空速选择器。各选择器按第 2.1.10 节读取所选数据，并分别形成 `data/valid/reset` 与诊断结果；各项有效性来自对应的所选数据。

CAS 的 `ChannelUsed` 使用 CAS 专用来源编号，其他数据使用公共来源编号。三路 CAS 均无效时仍可保留非零来源编码，输出是否有效由各项 `valid` 表示。

父级 `Calc_NavSourceSelection` 输出四项结果，见表 27。

**表 27  来源选择与父级输出**

| 输出             | 类型                 | 内容                                           |
| ---------------- | -------------------- | ---------------------------------------------- |
| `AdahruWeight` | `uint8[3]`         | 三台设备的数据有效性等级                       |
| `adahruSrc`    | `uint8`            | 公共来源编号；CAS 专用来源由 CAS 诊断项反映    |
| `AdahruData`   | `BUS_NavData`      | 来源选择封装的数据，以及父级写入的独立表决空速 |

来源及输出状态确定后，应用将结果转换为输出接口所需的数值尺度，再组装导航数据总线。五项速度相关数据采用以下缩放；状态字段继续使用各自选择器的结果。

#### 2.1.12 无线电高度选源

##### 2.1.12.1 输入数据与来源判定

无线电高度选源先根据两路高度的有效性确定本拍读取的来源；两路有效性相同时，地面采用固定优先顺序，飞行根据上一拍来源处理。因此，当前有效性与来源历史共同决定本拍读取哪一路，高度数值随后按共用选择器规则输出。

`Calc_VotedRA/SourceSelection` 接收高度输入 `raNormalInfos:Bus_SingleSignalNormalInfo[3]`，每项包含 `data`、`valid`、`isSynced` 和 `state`；另接收 `OnGnd`、前级导航数据 `AdahruData:BUS_NavData` 和诊断总线 `NavDataState:BUS_NavDataState`。后两者作为输出更新的基础，未赋值的字段保留原输入。

高度数组接口长度为 3，来源判定只读取第 1、2 路的 `valid`，第 3 路不参与选源；`isSynced` 也不作为此处的选择条件。

记两路有效标志为 `v1`、`v2`，上一拍来源为 `lastSelect`。来源编号通过单拍延迟保存，初值为 0。

**表 30  无线电高度来源选择规则**

| 条件                                            | 本拍来源 |
| ----------------------------------------------- | -------- |
| `v1=true`、`v2=false`                       | 第 1 路  |
| `v1=false`、`v2=true`                       | 第 2 路  |
| `v1=v2` 且 `OnGnd=true`                     | 第 1 路  |
| `v1=v2` 且 `OnGnd=false`、`lastSelect=2`  | 第 2 路  |
| `v1=v2` 且 `OnGnd=false`、`lastSelect!=2` | 第 1 路  |

`v1=v2` 同时包括两路均有效和两路均无效。后一情况下仍确定来源编号，但数据输出保持 `valid=false`；所选高度为该通道本拍数值，不保持历史有效高度。

##### 2.1.12.2 数据提取与输出更新

RA 选源调用 `SignalProcessingLib/SrcSelect`，采用第 2.1.10 节的数据提取、复位通知及诊断封装规则。其 `data/valid/reset` 输出封装为 `tSingleData`，写入 `raData.raRadioAlt_M`；来源编号通过 `RaSrc` 输出，取值为 1 或 2。两路原始高度的 `data/valid` 分别写入 `ra1RadioAlt_M` 和 `ra2RadioAlt_M`，这些原始字段在此处不另行生成 `reset`。

诊断结果写入 `raState.raRadioAlt_M`，其 `VoterType=SourceSelect`，`ChannelUsed` 的当前可达值为 1、2；其他输入诊断字段保留。共享选择器仍保留三项输入 `state`，其中第 3 项诊断的传递不表示第 3 路参与选源。

例如，飞行中原来源为第 2 路，两路均无效时仍保留编号 2，但有效来源历史变为 0；随后第 2 路恢复有效，即使 `RaSrc` 未变，也会产生 `reset=true`。这一行为直接采用第 2.1.10 节的共用复位判定。

#### 2.1.13 地面站消息选源

##### 输入分组与优先来源

地面站输入按第 1.3.2 节的 Current／Left／Right 三个候选位置组织。`RemotePilotCtrl` 与 `RemoteFMCP` 分别依据 `PilotCtrlMsgValid`、`FmcpMsgValid` 选源；两组共享优先位置，但独立判断有效性，因此可以采用不同来源。

优先位置由本机 `fccId` 和主控 `activeFccId` 映射产生，位置 1／2／3 分别对应 Current／Left／Right。

**表 31  FCC 身份到优先输入位置的映射**

| 本机 fccId | activeFccId=PFCC1 | PFCC2        | PFCC3        |
| ---------: | ----------------- | ------------ | ------------ |
|          0 | Current（1）      | Right（3）   | Left（2）    |
|          1 | Left（2）         | Current（1） | Right（3）   |
|          2 | Right（3）        | Left（2）    | Current（1） |

本机编号或主控枚举未匹配时，优先位置为 0，表示未指定优先输入；仍按 Current→Left→Right 选择首个有效输入。该表用于本模型的选源控制，不替代物理接线或上游输入填充关系。

##### 选源判定与数据提取

每组消息优先采用指定位置的有效输入；未指定优先位置，或该位置的本组消息无效时，按 Current→Left→Right 的顺序选择第一路有效消息。两组分别执行以下判定，使用各自的消息有效标志：

```text
如果已指定优先位置，且该位置的本组消息有效：
    选择该位置
否则，如果 Current 的本组消息有效：
    选择 Current
否则，如果 Left 的本组消息有效：
    选择 Left
否则，如果 Right 的本组消息有效：
    选择 Right
否则：
    本组没有有效来源
```

选源结果编码为 `uint8` 类型的来源掩码 `h`：选中 Current、Left、Right 时，分别赋值为 1、2、4，在二进制表示中分别对应第 0、1、2 位为 1；没有有效来源时赋值为 0。每组最多选中一路，因此不会形成多个通道共同参与的编码。位置号 1／2／3 与来源掩码 1／2／4 分别用于定位输入和表示选源结果。

来源掩码随后用于消息提取、输出有效性判定和来源变化检测。该实现不进行三路业务数值比较，也不使用上一拍来源保持同级优先权；历史只用于检测来源变化。

数值路径按 `h=2` 读取 Left、`h=4` 读取 Right，其余情况读取 Current。因此全无效时，仍输出 Current 本拍消息的数值并置 `valid=false`，不保持上次有效消息，也不替换为零值。

##### 有效性与来源变化通知

两组选源内部均保存上一拍来源掩码，初值为 0，并计算：

```text
valid = (h > 0)
reset = (h[k] != h[k-1])
```

该变化通知未附加有效性门控：首次建立来源、有效来源切换及非零来源变为 0 均产生通知；来源掩码不变时不产生通知。与第 2.1.10 节的 `SrcSelect` 不同，此处事件还包括失去有效来源。

**表 32  地面站两组输出的继承规则**

| 项目                | RemotePilotCtrl                                       | RemoteFMCP                        |
| ------------------- | ----------------------------------------------------- | --------------------------------- |
| 业务项数            | 25：ValidBit、4 轴、10 个 RC_SW、Stick_Type、9 个 Key | 14：10 个按钮、4 个目标量         |
| 各项 valid          | 共用本组`h>0`                                       | 共用本组`h>0`                   |
| 最终各项 reset      | 共用本组来源变化通知                                  | 固定`false`；内部变化通知被终止 |
| 来源诊断 voterState | 根层终止，不随 GcsData 输出                           | 根层终止，不随 GcsData 输出       |

`ValidBit` 本身作为业务数据封装，本模块未解码它来分别构造四轴或各按键的有效性。因此，输出结构的 `valid` 表示本组消息存在有效来源，不替代该业务字段在后续环节的解释。

### 2.2 一致性监测与数据表决

比较先判断同一数据项的不同记录是否足够接近，并通过连续确认形成逐路状态；表决再结合这些状态与输入有效性确定参与通道，按通道组合形成结果。因此，先说明比较资格、配对和通道状态，再说明参与判定、数值计算及通知。某一路缺少一致性支持，不等于该路输入无效或已经确认失配。

参与比较的数值先适配到相同尺度。ADAHRU 的指定角度预处理、RA 的两路真实输入及占位、VDT／GPIO 的逐项组织和混合空速尺度分别在应用中交代。运行状态只为新增禁用提供许可，具体仍按[公共控制条件](#public-runtime-control)及本节各项条件判定。

#### 2.2.1 一致性监测的输入输出

本节沿用[第 1.3.1 节](#signal-state-terms)的有效性、一致性、失配与禁用定义。算法对同一数据项的三路输入进行两两比较，根据偏差及其持续过程形成每路的一致、失配和禁用状态。这些状态供后级表决或诊断使用；各应用是否以一致性限制数据使用，见应用说明。监控实例各自保存计数和通道历史；使用同一算法或参数不共享实例状态。

判定分为两层：三组配对先检查比较资格和数值差，连续计数把比较结果形成配对一致、失配及禁用请求；再将与某通道有关的两组请求综合为该通道状态。配对请求描述两路之间的关系，通道状态用于后级表决或诊断，不能直接把某一配对的结果当作本通道最终状态。

输入包括三路数值 `x_i`、各路有效标志 `v_i` 和 `inAir`，其中 `i=1、2、3`。`inAir` 控制是否允许将通道置为禁用，实际禁用还须满足禁用使能和失配条件。参与比较的数据应使用相同数值尺度；精度选择和必要转换由应用封装完成。输出为逐通道的一致状态 `isSynced`、失配状态 `isMissCompare` 和禁用状态 `isBanned`。

#### 2.2.2 一致性监测参数

**表 35  一致性监控参数**

| 参数          | 算法作用                                                 |
| ------------- | -------------------------------------------------------- |
| `MAXERROR`  | 两路数值允许的最大绝对差，单位与比较数据相同             |
| `MISSCMP`   | 配对失配请求的连续超差确认门限                           |
| `BANNED`    | 配对禁用请求的连续超差门限，与失配请求使用同一失配计数器 |
| `SYNCED`    | 配对一致请求的连续一致确认门限                           |
| `BANENABLE` | 大于 0 时允许新置位通道禁用；关闭使能不清除已有禁用历史  |

误差门限限定容许偏差，连续计数门限确认偏差或一致关系是否持续。禁用请求和通道禁用状态分层产生，后者还受与该通道有关的两组配对禁用请求、`inAir` 和禁用使能约束。

#### 2.2.3 配对比较与通道状态

##### 配对有效性与偏差判定

设置三组配对，分别比较 **(1,2)、(2,3)、(3,1)**。

某一路参与比较的条件为：**输入有效性 `v_i=true`，且上一拍未被禁用**。一对通道双方均满足该条件时，该**配对有效**。

记两路数据为 `x_i`、`x_j`，计算绝对差：

`e_ij = |x_i - x_j|`

本拍数值一致的判据为：

`e_ij ≤ MAXERROR`

##### 连续确认与配对请求

每个比较器设置连续一致计数 `c_s` 和连续失配计数 `c_m`，初值均为 0。

**表 36  配对有效且 MISSCMP、SYNCED 均大于 0 时的计数更新**

| 本拍比较结果         | 一致计数`c_s`            | 失配计数`c_m`                             |
| -------------------- | -------------------------- | ------------------------------------------- |
| `e_ij <= MAXERROR` | 加 1，最大保持在`SYNCED` | 清零                                        |
| 上述条件不成立       | 清零                       | 加 1，最大保持在`max(MISSCMP, BANNED, 0)` |

每段连续一致或连续超差过程的首拍，相应计数为 1。本拍使用更新后的计数产生请求：

```text
失配请求 = (c_m >= MISSCMP)
一致请求 = (c_s >= SYNCED) AND NOT 失配请求
禁用请求 = 失配请求 AND (c_m >= BANNED) AND (BANNED >= MISSCMP)
```

配对无效，或 `MISSCMP<=0`、`SYNCED<=0` 时，三类请求均为 `false`；当配对有效且 `MISSCMP>0、SYNCED>0`，重新进入计数分支时，两个计数器从初值重新开始。

连续计数用于确认偏差是否持续存在；数值一致时清零失配计数，超差时清零一致计数，避免零散超差累计触发失配。

##### 通道状态综合与历史保持

每一路使用与自身有关的两组比较结果。例如，通道 1 使用配对 `(1,2)` 和 `(3,1)`。按表 37 形成该路状态。

**表 37  通道状态综合规则**

| 输出状态与比较条件                              | 判定规则                                                                                                                  |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `isMissCompare`：与本通道有关的两组配对均有效 | 两组都提出失配请求时，本通道失配为 `true`；否则为 `false`                                                             |
| `isMissCompare`：仅一组配对有效               | 本通道失配采用这一有效配对的失配请求                                                                                      |
| `isMissCompare`：两组配对均无效               | 本通道失配为 `false`                                                                                                    |
| `isSynced`（一致）                            | 该路未失配、未禁用且至少一组配对有效，并且（任一相关配对提出一致请求，或上一拍该路已一致）时为 `true`；否则为 `false` |
| `isBanned`（禁用）                            | 两组都提出禁用请求，且 `inAir=true`、`BANENABLE>0` 时置位；置位后锁存，数据恢复一致不自动清除                         |

以通道 1 为例，它使用配对 `(1,2)` 和 `(3,1)`。两组均有效时，即使其中一组已提出失配请求，只要另一组未提出失配请求，通道 1 就不判为失配；若只有 `(1,2)` 有效，则通道 1 的失配状态采用该配对的请求。这里“有效”表示本组双方具备比较资格，“失配请求”还须经过连续超差确认。

一致历史和禁用历史分别保存，初值均为 `false`。一致状态按表 37 的当前条件及上一拍一致状态更新；禁用状态一旦置位，即使数据恢复一致也继续保持。

相关模型状态重新初始化时，这两类历史恢复初值。配对计数重新初始化、返回地面或关闭禁用使能均不清除已有通道禁用锁存。状态重新初始化与各数据输出中的 `reset` 通知作用不同；具体初始化触发由模型运行方式确定，本节仅说明已确认的状态初值及保持关系。`isSynced` 表示数值一致性，本模块不进行时间戳对齐。

三路互相比较只能提供相对一致性证据。仅有两路满足比较条件，且这两路之间的配对已提出失配请求时，两路的 `isMissCompare` 均为 `true`，不能据此确定哪一路真实正确。

#### 2.2.6 数据表决的输入输出

本节的有效性、一致性、参与掩码及复位通知采用[第 1.3.1 节](#signal-state-terms)定义。三通道表决根据每路数据的有效性和一致状态，决定哪些通道参与计算，再按通道组合执行直通、平均或中值计算。无通道参与时，保持上次输出数值，并将输出标为无效。

输入为三路数值及各自的有效性、一致状态。通道参与规则在第 2.2.7 节说明；计算时以 `x_1、x_2、x_3` 表示三路数值，以 `F` 表示三路全部参与时的计算方式配置，以 `data0` 表示历史数值初值。具体通道顺序、数值尺度及配置绑定见应用说明。

#### 2.2.7 参与通道判定

表决优先采用输入有效、且已被一致性监测标记为一致的通道；只要存在满足条件的通道，就采用全部满足条件的通道。没有这样的通道时，按应用配置决定是否允许采用唯一有效输入。

VDT／GPIO 库表决允许采用唯一有效输入。两处空速表决通过 `SpCPT.CASVoterType` 配置：等于 2 时不允许，其他值允许。该配置只影响没有有效且一致通道时的处理，不改变优先选取规则。

参与通道按以下顺序确定：

```text
如果存在“输入有效且标记为一致”的通道：
    采用全部同时满足这两个条件的通道

否则，如果允许采用唯一有效输入，
        且三路输入中恰好只有一路有效：
    采用该路

否则：
    不采用任何通道
```

因此，没有有效且一致通道时，即使应用允许单路使用，三路均无效或仍有两路、三路有效，也不采用任何通道。采用唯一有效输入不会将该路的一致状态改为真；该路可以用于本次输出，但仍未获得一致性确认。

参与通道确定后，将结果编码为 `chUsed`。该字段为 `uint8` 类型，第 0、1、2 位分别对应通道 1、2、3：参与则置 1，不参与则置 0。三位的权值分别为 1、2、4，因此编码值等于本拍所有参与通道的权值之和，等价计算如下：

```text
chUsed = 0

如果通道 1 参与：
    chUsed = chUsed + 1
如果通道 2 参与：
    chUsed = chUsed + 2
如果通道 3 参与：
    chUsed = chUsed + 4
```

例如，通道 1、3 参与时，`chUsed=1+4=5`，二进制为 `101`；没有通道参与时，`chUsed=0`。上述伪代码用于说明编码关系。编码依据最终参与判定，既包括因有效且一致而选中的通道，也包括按配置采用的唯一有效输入。

`chUsed` 同时用于数值计算分支选择、输出有效性判定和参与通道变化检测。有通道参与时，按通道组合执行单路直通、两路平均或三路平均／中值计算，并输出有效；没有通道参与时，保持上一拍表决数值并输出无效。各编码对应的计算分支见第 2.2.8 节，输出有效性及变化通知规则见第 2.2.9 节。

#### 2.2.8 分支计算与数值历史

单路参与时直接输出该路数值，两路参与时取两路平均；三路参与时，`F>0` 取算术平均，否则取中值。模型按 `chUsed` 激活对应计算分支，下表将这一规则与位编码对应。二进制位按通道 3、2、1 排列。

**表 46  参与通道组合与分支计算**

| `chUsed` | 二进制  | 参与通道 | 分支输出                                         |
| ---------: | ------- | -------- | ------------------------------------------------ |
|          1 | `001` | 1        | `x_1`                                          |
|          2 | `010` | 2        | `x_2`                                          |
|          3 | `011` | 1、2     | `(x_1+x_2)/2`                                  |
|          4 | `100` | 3        | `x_3`                                          |
|          5 | `101` | 1、3     | `(x_1+x_3)/2`                                  |
|          6 | `110` | 2、3     | `(x_2+x_3)/2`                                  |
|          7 | `111` | 1、2、3  | `F>0` 时取 `(x_1+x_2+x_3)/3`，否则取三路中值 |
|          0 | `000` | 无       | 默认分支：上一拍表决数值                         |

当前编码正常范围为 0～7，显式计算分支覆盖 1～7，默认分支用于无通道参与。默认分支对应历史保持，不产生新的测量值。

以 `k` 表示本拍、`k-1` 表示上一拍，记本拍表决值为 `z[k]`。当前分支结果直接输出并保存，供下一拍作为上一拍的表决值使用。无通道参与时 `z[k]=z[k-1]`；历史初值为 `data0`，连续无通道参与时持续保持。历史延迟位于反馈支路，不使所有正常计算结果额外延迟一拍。

#### 2.2.9 输出有效性与参与通道变化

输出有效性 `valid` 表示本拍是否有通道参与计算。为了报告数据首次可用、恢复可用或参与通道的变化，模型比较前后两拍的 `chUsed`：本拍有通道参与且组合发生变化时，输出 `reset=true`；本拍没有通道参与或组合不变时，`reset=false`。

参与通道历史的初值为 `uint8(0)`，因此首次出现参与通道也会产生通知。该历史用于检测通道变化，与第 2.2.8 节用于保持输出值的数值历史分别保存。

### 2.3 设备故障与冗余状态判定

前两节形成数据的使用结果，本节说明设备反馈和指定输入状态怎样形成故障代码及冗余丧失报告。两者采用不同表示：故障代码由条件分支确定，冗余丧失由状态位与检查掩码汇总。报告的有效性与设备数据是否可用分别判断；这些结果再由第三章 CCDL 模块组合为本机就绪及限制派遣信息。

`Calc_SysInfo` 将 FCC 缺失位和设备状态位字按组筛选汇总，写入 `BUS_SysInfoData` 的冗余丧失标志。`Calc_MCUSCUData` 根据 SCU 的有效性和设备反馈生成 `FaultStatus`、`ClawFaultStatus`。两条路径均按本拍输入进行组合判定，不包含第 2.1 节的连续异常确认、恢复等待或历史锁存。位掩码沿用第 1.3.4 节的约定，故障代码则按其分支条件解释。

#### 2.3.1 按配置掩码判定冗余丧失

##### 判据与配置作用

冗余丧失判定先按配置选出需要检查的状态位，再排除本设备组范围外的位；保留下来的任一位为 1，就输出该组冗余丧失为真。配置关闭某位，只使该位不参与本次汇总，不清除原状态，也不改变前级数据的有效性。

模型将状态位字、检查配置和本组位范围按位与，再判定结果是否大于零。以 `F` 表示本组状态位字、`M` 表示检查配置、`R` 表示本组位范围，计算关系为：

```text
checkedBits = bitand(bitand(F, M), R)
LossRedundancy = (checkedBits > 0)
```

`bitand` 表示按位与。该算法汇总已有状态，不比较测量数值或计算剩余设备数量；输入及位范围的对应见表 53。

##### VDT 状态输入的形成与使用

上表的 VDT 状态位字由前级指定杆位的原始有效性生成。以下用这一应用说明状态如何形成并进入同一掩码汇总规则，使输入状态、检查配置和最终冗余丧失标志能够完整对应。

`Calc_PilotInData` 为每个 Current／Left／Right 通道检查 VDT 数组第 1、2、5、6 项，即 `CSSU_X、CSSU_Y、LSSU_X、LSSU_Y`。对任一通道 `c`：

```text
fault_c = NOT (CSSU_X.valid AND CSSU_Y.valid
               AND LSSU_X.valid AND LSSU_Y.valid)
```

按第 1.3.4 节约定，将三个 `fault_c` 分别写入 `VdtCBIT` 的 bit0、bit1、bit2，再送入 `Calc_SysInfo`：

```text
指定杆位的原始 valid
  → 各通道四项有效性汇总
  → VdtCBIT
  → 检查掩码与低三位范围筛选
  → VdtLossRedundancy
```

RSSU 两项、GPIO 及一致性／失配／表决结果不参与这条汇总路径。四项任一无效即可置位，不等待比较计数；该检查反映指定杆位记录的有效性，并非对该通道所有操纵输入的完整故障判断。

#### 2.3.2 故障条件组合与状态编码

SCU 处理根据整体 `Valid` 及设备反馈 `INT_STS、EN_STS、STK_MON` 生成两种状态。以下代码均写入输出结构的 `data:uint8`。

通用 `FaultStatus` 按或逻辑形成：

```text
fault = NOT Valid OR (INT_STS == 0) OR (EN_STS == 0)
FaultStatus.data = 1，当 fault=true
FaultStatus.data = 0，当 fault=false
```

`ClawFaultStatus` 采用有优先级的分支。表内条件互斥；前项成立后不再由后项改变结果。

**表 54  SCU ClawFaultStatus 代码判定**

| 优先级 | 条件                                                                  | ClawFaultStatus.data |
| -----: | --------------------------------------------------------------------- | -------------------: |
|      1 | `Valid=false`                                                       |                    2 |
|      2 | `Valid=true` 且 `STK_MON==0`                                      |                    1 |
|      3 | `Valid=true`、`STK_MON!=0`，且（`INT_STS==0` 或 `EN_STS==0`） |                    2 |
|      4 | `Valid=true`、`STK_MON!=0`、`INT_STS!=0`、`EN_STS!=0`         |                    5 |

两个输出均为条件分支选定的状态代码，各位不分别表示独立故障，不能按位掩码或数值大小推定其含义。当前模型可确定 `ClawFaultStatus` 中代码 1、2、5 的赋值条件，但其正式故障名称仍须接口定义确认。`FaultStatus` 与 `ClawFaultStatus` 使用的条件和代码不同，前者未单独检查 `STK_MON`，不能把两者视为同一个故障标志的重复输出。

两项均按 `tU8Data={data:判定代码, valid:true, reset:false}` 封装。**设备无效时，位置反馈可以无效，故障报告本身仍可有效。** 因此 SCU 的 `Valid=false` 会使 `Position.valid=false`，同时输出 `FaultStatus.data=1`、`ClawFaultStatus.data=2`，且两项报告的 `valid` 均为 `true`。该设计使下游可读取无效设备的判定结果，而无需把“报告有效”解释为“设备正常”。

## 3 下游数据整合

第一阶段给出的数据和状态还需要按使用方的接口形成输出。各模块采用的条件不同：操纵输出把输入变成轴量和指令，导航输出换算和计算物理量并最终选源，设备与 FMS 输出按字段决定直传或保持，CCDL 组合就绪条件，显示和 DRMS 再组织所需状态。因此，本章以模块为单位，将各自的条件、计算、历史及接口结果放在一起解释；相同的基础机制按需引用第二章。

### 3.1 输出阶段的数据关系与公共说明

各模块读取第一阶段的不同结果，并行形成各使用方接口。操纵模块还输出空地值及有效性，导航模块据此封装空地字段；其余导航数值和状态由导航数据及物理量计算形成。CCDL 读取最终导航有效性、设备及操纵条件形成报告，同时从接收状态形成独立汇总。该汇总的就绪结果进入 SYS 和显示，限制派遣结果进入显示。

地面站与飞行员两份操纵消息均保留给显示，最终选定的 `Cockpit_In` 主要决定实际操纵输入及显示来源状态。FMS 直接读取 MPIO 的相应记录；DRMS 复制最终导航有效性结构，并在飞行员开关与地面站开关间选择备份激活输入。以下模块的组织顺序服务阅读，各段按实际数据依赖解释，不把章节顺序当作运行调度。

第二章输出的 `data/valid/reset` 在本章可能被拆成独立接口字段，也可能只取其中 `data`。某字段未继续传递有效性，不代表本模块补做了上游监测；某标量保留旧值，也不代表输入记录仍然有效。各节分别说明这些消费规则和固定默认值。

### 3.2 操纵输入与指令生成

`Calc_PilotIn_ToClaw` 将前级地面站、飞行员操纵及 MPIO 记录转换为控制律和其他输出模块使用的操纵接口。地面站与飞行员支路平行处理：各自形成操纵数值、有效标志和指令，分别输出为 `RC`、`PilotIn`；再按配置选定其中一条支路，形成 `PilotData`，在 VE25SP 根层以 `Cockpit_In` 传递。两条支路各自的结果仍被保留，供就绪检查、显示等路径使用，未选为最终来源不会停止该支路的内部历史更新。

操纵轴数值换算与使用资格并行形成；离散输入则依据各项规则生成操作事件或持续指令。模块还形成 `Air2Gnd` 及 `Air2GndValid`，供导航输出模块生成最终空地字段。这些输出分别通过数值换算、事件识别、状态更新及来源选择形成，输入无效时的处理由各路径独立确定。

#### 3.2.2 操纵量死区、量程转换与限幅

操纵量转换将输入零位附近的小变化置零，将死区外的剩余行程换算为规定的输出行程，并将结果限制在输出范围内。地面站支路按归一化输入范围进行换算，飞行员支路接收已经过表决的杆位数值；两者采用相同的“扣除死区后重新展开行程”方法，但输入尺度不同，不能共用同一数值公式。

令 `x` 为当前输入，`U` 为输出正向上限，`L` 为输出负向下限的绝对值，且 `U>0、L>0`。当前死区比例为 0.05，死区外剩余比例为 0.95。输出结果记为 `y`，最后统一限制在 `[-L, U]`。这些数值在当前各换算子系统中由常量提供，没有另设独立的量程配置入口。

##### 3.2.2.1 地面站操纵量换算

地面站接口对 `chAileron、chElevator、chThrottle` 分别定义滚转、俯仰和油门操纵轴，数值范围为 −1～+1；协议中的原始字段为 `int16_t`，本节公式的 `x` 则是进入 SP 后 `GcsData` 对应记录中的 `single` 数值，不是原始整数码。`chRudder` 表示偏航操纵轴，但同一接口表未填写其比例及上下限，不能仅凭本节双向公式补写为已确认的正式输入范围。

地面站输入的正、负死区边界分别为 0.05、−0.05。超过正死区时减去 0.05，再将剩余输入按正向量程换算；超过负死区时加上 0.05，再按负向量程换算。位于死区内或恰在边界时输出零。

```text
如果 x > 0.05：
    换算值 = (x - 0.05) / 0.95 × U
否则，如果 x < -0.05：
    换算值 = (x + 0.05) / 0.95 × L
否则：
    换算值 = 0

y = 将换算值限制在 [-L, U]
```

#### 3.2.4 事件识别与脉冲处理

离散操纵输入可以形成一次操作事件，也可以形成持续保留的开关状态。事件比较当前与历史输入，只在规定变化发生时触发；持续状态依据合格输入更新，其余情况保持。两条操纵支路虽使用同名输出字段，仍可能采用不同的生成方式：以下先说明事件及脉冲，再说明持续状态的更新，不能将所有开关统一解释为沿触发或电平直通。

##### 3.2.4.1 有效输入变化的事件识别

事件识别保存上一拍输入，用当前值与上一拍值判断是否发生了指定变化。对于地面站 TRC 和停车请求，当前与上一拍记录均须有效，且当前记录的 `reset=false`，才接受该变化。这样，记录首次有效、恢复有效或来源变化所带来的通知不会在当前拍被当作这类开关操作事件。

```text
如果当前记录有效、上一拍记录有效，且当前 reset 为 false：
    根据本拍数值与上一拍数值，判断是否发生规定变化
否则：
    本拍不产生该事件

保存本拍输入记录，供下一拍比较
```

输入历史每拍更新，包括无效记录；初始化时历史有效性为假。因此，刚由无效转为有效的第一拍不能通过前后拍有效性检查。这些历史延迟没有由输入 `reset` 驱动的清零端口；`reset` 在此作为事件判定条件使用。

**表 60  沿识别的应用条件**

| 输出或事件用途 | 输入与规定变化 | 当前 `reset` 的作用 |
|---|---|---|
| 地面站 TRC 操作事件 | `KeyTRC` 或 `SW7` 从 0 变为 1；两路事件取逻辑或 | 当前对应输入 `reset=true` 时不产生该路新事件 |
| 地面站停车请求 `TEST_IN.Request_Stop_GNDStation_b` | `KeyEmergency` 从 0 变为 1，或 `SW1` 从 1 变为 0 | 同上；两路事件取逻辑或，当前模型不再延长该输出 |
| MFD 的电机检查、舵面检查及预检事件 | `MotorCheck`、`SurfaceCheck`、`PreflightCheckValid` 进入规定编码；具体编码见第 3.2.5 节 | 只检查前后拍有效性及数值变化，不读取这些记录的 `reset` |

表中各类事件共同使用前后拍比较，但并未使用完全相同的资格条件。MFD 检查事件的判据为“当前值等于目标编码，上一拍值不等于该编码”，并不要求上一拍必须为 0；TRC 和停车请求则要求表中指定的 0／1 变化。

##### 3.2.4.2 脉冲延长与有效电平保持

地面站 TRC 将第 3.2.4.1 节形成的一次操作事件延长，避免输出只在触发拍为真。当前实现将本拍事件与其前 1、2、3、4 拍历史作逻辑或，形成 `TRCOn_PltIn_b`：

```text
TRC 输出 = 本拍发生事件
           或前 1 拍发生事件
           或前 2 拍发生事件
           或前 3 拍发生事件
           或前 4 拍发生事件
```

事件历史初值均为假。孤立的一次事件使输出从触发拍起连续 5 个执行拍为真；期间若再次发生事件，输出持续时间按后续事件的历史窗口延续。脉冲形成后不再由当前输入的有效性或 `reset` 门控，因此后续输入无效或出现 `reset` 不会提前截断已经形成的脉冲。这里的拍数由当前模型延迟配置及同源参数读取记录确认；未据此换算未验证的实际持续时间。

飞行员 TRC 采用另一条规则：`GPIO[6]` 有效时，根据其数值是否大于 0 更新输出；无效时保持上一拍输出，初值为假。它不执行 TRC 沿识别、脉冲延长或 `reset` 检查。飞行员的 AP 断开、升力电机锁定和多旋翼保护也使用相同的有效电平保持方式。

**表 61  飞行员支路的有效电平更新**

| 输入项 | 输出字段 | 有效时的更新 | 无效时及初值 |
|---|---|---|---|
| `GPIO[6]` | `TRCOn_PltIn_b` | 输入数值大于 0 时为真，否则为假 | 无效时保持；初值假 |
| `GPIO[8]` | `AP_Disengage_SW` | 同上 | 同上 |
| `GPIO[2]` | `LiftMotor_lock_SW_b` | 同上 | 同上 |
| `GPIO[4]` | `MCProtOn_PltIn_b` | 同上 | 同上 |

飞行员降级状态从 `GPIO[3]` 按同一有效电平保持规则形成，并写入 `TEST_IN.Enable_Degrade_b`。当该保持结果由真变为假时，产生一拍升级事件，交给第 3.2.5 节的 MFD 判定。输入无效期间保持结果不变，不会仅因有效性丢失而产生升级事件；恢复有效后，如果新数值使保持结果从真变为假，仍可产生该事件。

#### 3.2.5 持续指令的优先判定与历史保持

##### 3.2.5.1 地面站开关指令

地面站的降级、保护等输出需要同时响应面板指令和遥控器开关。输出按置真、置假、历史保持的优先顺序确定；两类更新条件同时成立时置真优先，均不成立时保持历史值。每项独立保存输出，初值均为假。

```text
如果置真条件成立：
    当前指令 = true
否则，如果置假条件成立：
    当前指令 = false
否则：
    当前指令 = 上一拍指令

保存当前指令，供下一拍使用
```

**表 62  地面站持续指令条件**

| 输出字段 | 置真条件 | 置假条件 |
|---|---|---|
| `TEST_IN.Enable_Degrade_b` | 有效 `KeyFcModeSel=1`，或有效 `SW4=1` | 有效 `KeyFcModeSel=0`，或有效 `SW4=0` |
| `TEST_IN.Enable_THRDir_b` | 有效 `SW6=0` 或 2 | 有效 `SW6=1` |
| `MCProtOn_PltIn_b` | 有效 `KeyMultcopterProt=1`，或有效 `SW5=0` | 有效 `KeyMultcopterProt=0`，或有效 `SW5=2` |
| `AP_Disengage_SW` | 有效 `KeyAP=1`，或有效 `SW0=0` 或 2 | 有效 `KeyAP=0`，或有效 `SW0=1` |
| `LiftMotor_lock_SW_b` | 有效 `KeyLockSW=1` | 有效 `KeyLockSW=0` |

表中的“有效”均指对应输入记录自身的 `valid=true`。未列出的数值编码不构成该路更新条件；输入无效也不构成置真或置假条件。如果另一输入仍能形成更新条件，输出继续按该条件更新；只有全部更新条件均不成立时才保持。此组指令不读取输入的 `reset`，也不采用异常连续计数。

##### 3.2.5.2 MFD 指令编码与优先顺序

MFD 输出将模式升级和检查操作汇总为单个枚举指令。当同一拍出现多个事件时，模型按固定顺序只采用其中一个；未形成新事件时，仅在当前降级且原指令为模式升级时清除，其他情况保持已有编码。因此，该字段虽然由事件更新，输出本身仍是持续保持的指令编码，而非自动清除的一拍脉冲。

两条操纵支路共用以下检查事件：当前与上一拍对应 MPIO 记录均有效，并且当前进入目标编码、上一拍尚不为该编码。事件形成后，按表中顺序参与 MFD 判定。

**表 63  MFD 检查事件与编码**

| 检查事件的优先顺序 | 输入进入的目标编码 | MFD 结果 |
|---:|---|---|
| 1 | `MotorCheck=1` | 2：`MtrCheckIn` |
| 2 | `MotorCheck=2` | 3：`MtrCheckOut` |
| 3 | `SurfaceCheck=1` | 4：`SurfCheckIn` |
| 4 | `SurfaceCheck=2` | 5：`SurfCheckOut` |
| 5 | `PreflightCheckValid=2` | 6：`SysReady` |

模式升级的产生条件由操纵来源决定。地面站支路要求当前降级指令为假，且 `KeyFcModeSel` 或 `SW4` 在前后两拍均有效并从 1 变为 0；飞行员支路使用第 3.2.4.2 节由降级保持结果下降沿形成的升级事件。两者均将模式升级置于上述检查事件之前。

完整更新顺序如下，其中模式升级编码为 1（`ModeUpgrade`），无指令编码为 0（`None`）：

```text
如果本拍形成模式升级事件：
    MFD = ModeUpgrade
否则，如果形成电机检查进入事件：
    MFD = MtrCheckIn
否则，如果形成电机检查退出事件：
    MFD = MtrCheckOut
否则，如果形成舵面检查进入事件：
    MFD = SurfCheckIn
否则，如果形成舵面检查退出事件：
    MFD = SurfCheckOut
否则，如果形成预检就绪事件：
    MFD = SysReady
否则，如果当前降级指令为真，且上一拍 MFD 为 ModeUpgrade：
    MFD = None
否则：
    MFD = 上一拍 MFD
```

MFD 历史初值为 `None`。降级条件只在未命中更高优先事件、且历史指令为 `ModeUpgrade` 时将其清除；它不会统一清除检查类编码 2～6。各检查输入的历史每拍更新，MFD 输出也每拍回写其独立历史；当前实现没有将输入 `reset` 用作这两类历史的复位信号。

#### 3.2.6 输出封装与操纵来源

处理后的操纵数值、有效标志、布尔指令及 MFD 枚举共同写入 `BUS_PILOT_IN`。轴数值带有各自的布尔有效标志；TRC、保护、AP 断开、锁定和 `TEST_IN` 中的指令直接输出布尔值；MFD 输出枚举值。这些指令字段没有再附带单独的 `valid/reset`，其输入有效性已参与本模块的更新判定，不能从保持的指令值反推当前原始开关仍有效。

除上述事件与历史指令外，部分字段直接由本拍条件形成：地面站失联标志在 `StickType` 无效或其数值为 0 时为真；飞行员失联标志在 CP 两侧杆轴及 CS 两操纵轴的有效标志未全部为真时为真，FO 两轴不参与该判断。地面站扫频使能要求 `SW8` 有效且数值为 1。它们不使用本模块持续指令的置真／置假保持规则。

两支路均从 MPIO 填入上电及高压状态：上电数值由 `HiVltgSW.data==2` 形成，上电有效性要求该输入有效且数值非 0；高压状态在 `HiVltgSts.valid=true` 时转换为对应枚举，否则输出 `Unknow`。地面站与飞行员支路分别将来源身份置为 `Primary` 和 `SideStick`。

未启用字段保留固定值。地面站 `TEST_IN.Enable_ResetFromExt_b=false`，`Init_X0_Vector` 为五项 `single(0)`。飞行员支路以零值 `BUS_TEST_IN` 为基础，只覆写 `Enable_PLTLost_b` 和 `Enable_Degrade_b`；`Enable_THRDir_b、Request_Stop_GNDStation_b、Enable_SwpTest_b、Enable_ResetFromExt_b` 保持为假，`Init_X0_Vector` 五项保持为零。这些固定值不参与本模块的指令状态更新，不能将字段存在解释为相应功能已经启用。

两支路均持续生成自身输出，分别保留在 `RC`、`PilotIn` 端口。最终 `PilotData` 在 `SpCPT.PilotInSelect=1` 时采用地面站支路，其他值采用飞行员支路；当前字典保存值为 `int32(1)`，该值不代表未读取的运行会话配置。选择发生在两支路处理之后，不因本拍最终未采用某支路而停止其内部历史更新。该 `PilotData` 在 VE25SP 根层送入 `Cockpit_In`；`RC`、`PilotIn` 保持各自独立结果。空地输出再依据所选结果的 `PilotSource` 读取对应支路的数值与有效性；若来源身份不属于上述两类则保持既有空地输出，其历史初值为零／假。`Air2Gnd` 与 `Air2GndValid` 分别送入 `Calc_NAVMsg_ToClaw`，本模块没有将它们改写为前级运行状态分类使用的 `OnGnd`。

实现定位：[Calc_PilotIn_ToClaw.slx](../sp/04_Design/Calc_PilotIn_ToClaw/specification/Calc_PilotIn_ToClaw.slx) 的地面站 TRC SID492、停车事件 SID337、持续指令 SID280/307/446/475/521、MFD SID368；飞行员电平保持 SID708/715/790/830、降级及升级 SID779、MFD SID722；总线封装 SID108/552、最终选择 SID22/23/27/31、空地选择 SID48。枚举编码见 [ENUM_Key_MFD.m](../sp/04_Design/common/libs/sldd/ENUM_Key_MFD.m)，总线定义见 [SP_Step_New.sldd](../sp/04_Design/common/specification/data_types/SP_Step_New.sldd)。延迟配置的同源参数证据见本次静态复核记录。

固定字段及根层连接定位：GCS 的 `TEST_IN` 构造 SID114 第6/7输入来自 SID265/266；飞行员零总线 SID679 经 SID557进入总线，SID556只覆写上述两项 `TEST_IN` 字段。根层 `VE25SP` SID376 的三路操纵输出分别进入 `Cockpit_In、PilotIn、RC`，两个空地输出经 SID400/401及SID402/403进入导航输出模型 SID375。


### 3.3 导航数据生成

导航数据生成接收前级已经监测、选源或表决的导航记录，形成送往控制律的数值及状态。前级确定了候选数据和使用状态，本级还需要完成接口数值转换、多个分量的状态合成，以及气压高度和真空速计算；这些结果形成后，再按各输出量的配置和资格决定最终采用哪条路径，将已有记录与新计算结果组织为最终导航消息。

#### 3.3.1 输入与处理关系

输入 `NavData:BUS_NavData` 保留 ADAHRU 已选出的单项记录、ADAHRU 三路 CAS 表决结果、FTADC 处理记录和混合空速表决结果，以及 RA 高度记录。各数值记录所附的 `valid/reset` 已由前级形成；本级在使用这些记录时，仍须按具体输出规则决定直接传递、组合或替换状态。

本级还接收操纵输入模块形成的 `Air2Gnd` 和 `Air2GndValid`。它们表示已选操纵来源提供的空地值及其有效性，与第一阶段依据 VTOL 运行状态得到的地面／飞行策略条件分别使用。这里不重新作运行状态分类。

实现上先以 ADAHRU 已选出的导航项及 RA 等记录组织基础消息，同时从 FTADC 压力和 ADAHRU 温度形成计算结果。最后只替换各输出项对应的数值、有效性和通知，其余字段保留。基础消息中的数值转换与分量状态合成各自按输入计算；物理量计算及后续选源的条件在相应处理处说明。

#### 3.3.2 基础导航消息与分量状态

##### 3.3.2.1 数值尺度与正方向

基础导航消息先按控制律接口所需的数值尺度和正方向整理前级结果。角度及角速度乘转换系数，垂向速度取负，比力既保留原数值又形成过载量，静压另换算为接口压力。这些简单运算不引入新的历史状态，也不因执行了换算而重新确认数据有效；相应有效性与通知按所选记录或数据组的规则传递。下表的 `ax、ay、az` 分别表示输入的 X、Y、Z 轴比力。

**表 64 导航输出的数值转换**

| 应用 | 数值关系 | 状态处理与位置 |
|---|---|---|
| 横滚角、俯仰角、真航向角；P、Q、R 角速度 | 弧度或 rad/s = 角度或 deg/s × `SpCPF.d2r` | 数值转换；横滚／俯仰和三轴角速度的状态按第 3.3.2.2 节合成；`Calc_NAVMsg_ToClaw` SID123～125、129～131 |
| GPS 或气压高度变化率转垂向速度 | 垂向速度 = −所选高度变化率 | 所选记录状态同步传递；来源判定见第 3.3.4 节；SID327、199 |
| 三轴比力转过载量 | `Nx=ax/g`，`Ny=ay/g`，`Nz=−az/g`，其中 `g=SpCPF.g` | 三轴比力本身仍以 m/s² 原值输出；只有 `Nz_IRU_g` 路径对 Z 轴取负，`Sfor_z_RB_mps2` 不取负；SID126～128、328 |
| FTADC 静压转接口压力 | 压力 Pa = 静压 kPa × 1000 | 写入 `Frt_psi_Pa`，有效性由静压记录传入 `Frt_psi_Valid_b`；SID132、176、177 |

上述角度转换不包括经纬度、迎角和侧滑角，它们在导航输出中保留原数值并使用 `_deg` 字段。高度及已完成尺度转换的速度也直接传递，不重复缩放。相同输入可以同时形成不同表示：例如三轴比力保留原数值，写入 `_mps2` 字段，并另行生成以重力加速度为尺度的过载量。

`SP_Parameters.sldd` 保存 `SpCPF.d2r=single(0.0174532924)`、`SpCPF.g=single(9.8004)`；定义脚本 `SpCPF_define.m` 将 `d2r` 定义为 `single(pi/180)`。表中的压力换算因子 1000 为固定常数。角度、压力及比力的单位表述沿用本级输入／输出字段的数值约定；目前 ADAHRU／FTADC 相关总线的单位元数据未填写，正式采集接口的单位仍待对应文件确认，前级速度缩放见第 2.1.11.6、2.2.10 节，不能仅凭其中的除以 3.6 就认定全部原始输入为 km/h。坐标系的完整轴向约定同样以接口定义为依据，不由一个取负运算推定整个坐标变换。

##### 3.3.2.2 多分量有效性与通知

一个输出量需要多个输入分量共同使用时，输出有效性应反映整组数据是否齐备，输出通知则应保留任一分量发生的通知。当前导航输出对这两类信息分别处理：全部分量有效时，组有效性才为真；任一分量的 `reset` 为真时，组通知即为真。

```text
组有效性 = 所有组成分量的 valid 均为 true
组通知   = 至少一个组成分量的 reset 为 true
```

这两个判定相互独立。某一分量发出通知，而另一分量无效时，组输出可以同时出现 `valid=false` 与 `reset=true`；组通知不表示整组数据已经恢复可用。数值分量仍分别传递或换算，本级没有因组无效而统一保持整组历史数值。

**表 65 组合状态的应用**

| 输出数据组 | 参与合成的输入分量 | 输出状态字段 |
|---|---|---|
| 水平位置 | 经度、纬度 | `Pos_XY_Valid`、`Pos_XY_Reset` |
| 水平速度 | 北向速度、东向速度 | `Vel_XY_Valid`、`Vel_XY_Reset` |
| 横滚／俯仰姿态 | 横滚角、俯仰角 | `Att_RP_Valid`、`Att_RP_Reset` |
| 三轴角速度 | P、Q、R | `Rot_Valid`、`Rot_Reset` |
| 三轴比力 | X、Y、Z 轴比力 | `Sfor_Valid`、`Sfor_Reset` |

组有效性写入 `Claw_Nav_Msg.Valid_Status`，组通知写入 `Claw_Nav_Msg.Reset_Status`；相应数值写入同一导航消息中的数据字段。这里合成的是已有分量状态，不重新执行一致性比较或异常确认。物理量换算见第 3.3.2.1 节；压力与温度共同参与计算时还存在计算条件约束，见第 3.3.3 节。

#### 3.3.3 气压高度与真空速计算

当前实现以 FTADC 静压、总压以及 ADAHRU 温度记录计算气压高度和真空速，并分别形成数值、有效性与通知，供第 3.3.4 节进行最终来源选择。计算没有独立的异常计数或历史数值保持；输入状态和数值条件共同决定结果能否被采用。

以下以 `Ps` 表示 `ftadcStaticPressure_kPa.data`，`Pt` 表示 `ftadcTotalPressure_kPa.data`，`T` 表示实际接入的 `adahruStaticTemp_C.data`。本节按这些字段后缀及计算常数所表达的 kPa、℃ 约定解释公式；上游正式采集接口的单位仍按第 3.3.2.1 节保留待确认。各输入记录另带 `valid` 和 `reset`。公式按当前活动模型列出，不因内部子系统名称含有 CAS 而将其解释为 CAS 压力推导算法。

##### 3.3.3.1 静压计算气压高度

气压高度在静压不低于 22.632 kPa 时按压力关系计算；低于该门限时输出固定值 11000 m，并将结果置为无效。计算关系为：

```text
如果 Ps >= single(22.632)：
    气压高度 = [1 − (Ps / 101.325)^(1 / 5.255879)] / 2.25577e-5
否则：
    气压高度 = 11000

气压高度有效 = 静压 valid AND (Ps >= single(22.632))
气压高度 reset = 静压 reset
```

数值分支只依据静压大小，输入的 `valid` 参与输出有效性判定。因此，静压记录无效而数值仍处于计算区间时，本级仍输出公式计算值，同时将其标记为无效；不会在本级保持上一拍高度。等于门限时进入计算分支。低压区间的对数计算块在当前模型中已注释停用，不能作为当前输出公式说明。

##### 3.3.3.2 压力比计算 Mach

Mach 计算先利用总压与静压的差值形成无量纲压力比，再进行幂运算与开方。输入有效性、压差符号及计算值上限共同约束结果：压力输入无效或压差为负时，输出 0 且无效；条件满足但计算值未通过不大于 1 的检查时，输出 1 且无效。

定义压差 `ΔP=Pt−Ps`，按当前模型的数值关系计算原始值：

```text
原始 Mach = sqrt{5 × [(1 + ΔP / Ps)^(1 / 3.5) − 1]}
压力条件 = 静压 valid AND 总压 valid AND (ΔP >= 0)

如果压力条件不成立：
    Mach = 0
    Mach 有效 = false
否则，如果原始 Mach <= 1：
    Mach = 原始 Mach
    Mach 有效 = true
否则：
    Mach = 1
    Mach 有效 = false

Mach reset = 静压 reset OR 总压 reset
```

这里的 0 和 1 是相应分支的数值输出，使用方仍须依据有效性判断是否采用。模型中除法和幂运算位于选择块之前，没有独立的 `Ps>0` 保护；上述输出分支不应解释为阻止所有无效输入进入数值运算。压差等于零、压力条件满足且静压为正时，Mach 为 0 并有效；正常有限输入产生的原始 Mach 等于 1 时仍可有效。

##### 3.3.3.3 Mach 与温度计算真空速

真空速将 Mach 与温度组合，按以下公式形成 m/s 数值：

```text
TAS = (72.168467 / 3.6) × sqrt(T + 273.15) × Mach
      / sqrt(1 + 0.1995 × Mach²)

TAS 有效 = Mach 有效 AND 温度 valid AND 气压高度有效
TAS reset = Mach reset OR 温度 reset
```

其中，温度支路先以 Mach 有效和温度有效形成计算有效性，外围再与气压高度有效性相与。因此，即使 Mach 和温度各自有效，静压低于气压高度门限时，最终 TAS 仍为无效。通知按输入通知合成，没有再用 TAS 有效性门控。

该公式每拍依据当前数值形成结果，当前支路没有独立的温度范围检查或无效时数值保持。实际输入字段为 ADAHRU 静温记录；这里只记录该绑定和活动公式，不将其自行改写为另一类温度输入，也不据公式名称补充当前模型没有实现的温度修正。

#### 3.3.4 输出来源判定

基础导航消息和压力计算结果形成后，本级按输出量分别确定最终来源。TAS 与气压高度在计算结果符合条件时替换 ADAHRU 结果；垂向速度、迎角／侧滑角和 CAS 则各有自己的选择条件。每次替换同时处理该项数值、有效性和通知，未涉及的导航字段保留。

##### 3.3.4.1 垂向速度与迎角／侧滑角选择

垂向速度通常使用 GPS 高度变化率；当 ADAHRU 单源 CAS 有效、其数值严格大于配置门限，且气压高度变化率有效时，改用气压高度变化率。两类高度变化率均取负后写入垂向速度，所选记录的有效性与通知同步传递。

```text
如果 ADAHRU 单源 CAS 有效，且 CAS > AltRateCASSelect，
    并且气压高度变化率有效：
    垂向速度 = -气压高度变化率
    采用气压高度变化率的 valid 和 reset
否则：
    垂向速度 = -GPS 高度变化率
    采用 GPS 高度变化率的 valid 和 reset
```

这里的门限判定使用 `adahruCAS_MPS`，不是本级最终选定的 CAS。未满足切换条件时直接采用 GPS 路径，即使 GPS 记录无效，也按其状态输出；没有额外的来源搜索、数值保持或来源变化通知。

迎角和侧滑角共同受 `SpCPT.AOADataSelect` 控制：等于 1 时，两项均采用 FTADC 记录；其他值保留 ADAHRU 记录。每项的数值、有效性和通知随所选记录传递，选择条件不包含所选数据的有效性，因此不会因 FTADC 某项无效而自动改用 ADAHRU。

##### 3.3.4.2 TAS 与气压高度选择

TAS 和气压高度各自先取得 ADAHRU 已选出的结果。当 `SpCPT.AirDataSelect=1`，且本级对应的压力计算结果有效时，采用该计算结果；否则保留 ADAHRU 结果。两项分别判断有效性，可以在同一拍采用不同来源。压力计算的输入、公式及有效性条件见第 3.3.3 节。

采用计算结果时，输出有效性取该计算结果的有效性，并按下式形成通知：

```text
输出 reset = 计算结果的 reset OR NOT 上一拍计算结果的 valid
```

上一拍有效性分别保存在单拍历史中，初值为假。因此，在本拍采用计算结果的前提下，该候选结果首次有效或由无效恢复为有效时会产生通知，输入记录带来的通知也被保留。这些历史保存的是候选计算结果的有效性，并非上一拍实际采用的来源；不能将该通知解释为覆盖所有配置切换的来源变化检测。保留 ADAHRU 结果时，其 `reset` 直接随记录传递。

##### 3.3.4.3 CAS 最终选择

CAS 的选择先由 `SpCPT.CASVoterType` 决定采用单源结果还是表决结果，再由 `SpCPT.AirDataSelect` 指定是否使用 FTADC 路径。规则如下：

```text
如果 CASVoterType = 1：
    如果 AirDataSelect = 1 且 FTADC CAS 有效：
        采用 FTADC CAS
    否则：
        采用 ADAHRU 单源 CAS
否则：
    如果 AirDataSelect = 1：
        采用 FTADC 与 ADAHRU 的混合空速表决结果
    否则：
        采用 ADAHRU 三路空速表决结果
```

单源分支采用 FTADC 时，其通知为 `FTADC CAS.reset OR NOT 上一拍 FTADC CAS.valid`，历史初值为假；采用 ADAHRU 时直接传递对应记录。表决分支则直接传递所选表决记录的数值、有效性和通知，所选结果无效时不再切换到另一个表决结果。若前级表决正在保持历史数值，该保持结果及无效标志一并传至本级。

上述 `CASVoterType=1／非1` 是输出层的选择条件；第 2.2 节内部表决在没有有效且一致通道时使用 `CASVoterType=2／非2` 的条件。两者作用位置不同：前者确定最终采用哪类 CAS 结果，后者确定参与表决的通道。

**表 66 导航输出层参数与保存配置**

| 参数 | 作用 | 字典保存值 |
|---|---|---|
| `SpCPT.AirDataSelect` | 等于 1 时启用 FTADC／压力计算路径；其他值采用相应 ADAHRU 路径，具体是否要求有效按上述各项规则处理 | `int32(1)` |

#### 3.3.5 输出封装与后续使用

最终导航消息使用 `BUS_NAV_IN`：数值字段与 `Valid_Status`、`Reset_Status` 分开保存。单项状态按最终选定记录传递，多分量状态按本节的合成规则形成；数值输出、有效性和通知分别保留其实际含义，不能由某项存在数值就认定它当前有效。

Mach 作为内部 `tSingleData` 记录传给 TAS 计算，其数值、有效性和通知不作为独立 Mach 字段对外输出。气压高度和 TAS 各自向外围提供数值、有效性和通知，由最终来源选择决定是否写入控制律导航消息。独立的 `FtadcLog` 则记录这两项计算结果以及 FTADC 原 CAS 的数值和有效性，不随最终来源选择而改写。因此，日志中的计算结果不表示它们已经被选为最终导航来源。

操纵空地输入直接映射为以下两个字段，本级不再增加有效性判定或历史保持：

### 3.4 CCDL 报文与系统就绪

`Calc_CcdlMsg_Out` 的系统就绪判定综合导航数据检查、设备冗余状态及预检、操纵条件，形成可对外报告的本机状态。同时，SP 还接收各计算机已经报告的状态，按配置形成供本机输出使用的汇总结果。两条路径的输入和输出不同：本机新生成结果写入 `SpCcdlOut.Data.SysReady`，多机汇总读取 `SysInfoData` 的 `Current/Left/Right` 状态，并产生独立的 `SysReady` 输出。

#### 3.4.1 导航数据组连续有效确认

导航检查使用最终控制律导航接口 `Claw_Nav_Msg.Valid_Status`，检查的是对应数据组当前是否满足使用条件，不直接比较原始设备数值。同组包含多个有效标志时，先要求全部标志为真，再对该组作连续确认。

每组配置值控制确认门限。名称中的 `Enable` 不仅表示布尔开关：配置为 0 时该组检查直接通过，正值表示需要由计数达到相应门限才能通过。当前五组输入及保存配置如下。

**表 68 导航数据组检查配置**

| 检查组 | 同组必须成立的有效标志 | `SpCPT` 配置及保存值 | 检查结果去向 |
|---|---|---|---|
| 惯性与速度 | `Vel_XY_Valid`、`Vel_Z_Valid`、`Att_RP_Valid`、`Att_Y_Valid`、`Rot_Valid`、`Sfor_Valid` | `Enable_AdahruCheck=int32(10)` | 与下列位置、大气、迎角／侧滑角组相与，形成导航综合检查结果 |
| 位置 | `Pos_XY_Valid`、`h_AMSL_Valid` | `Enable_GpsCheck=int32(0)` | 同上 |
| 大气数据 | `h_BARO_Valid`、`Vel_CAS_Valid`、`Vel_TAS_Valid` | `Enable_AdcCheck=int32(0)` | 同上 |
| 迎角／侧滑角 | `Alpha_ADS_Valid`、`Beta_ADS_Valid` | `Enable_AdcExpCheck=int32(0)` | 同上 |
| 无线电高度 | `h_AGL_Valid` | `Enable_RaCheck=int32(10)` | 独立形成无线电高度检查结果 |

各组独立保存 `uint32` 计数，初值为 0。组条件不成立时复位计数；条件持续成立时累计，计数经 0 至门限的限幅后用于判定。确认结果直接取“限幅后的计数达到门限”，没有另外保存“曾经通过”的锁存状态。因此，正门限下条件失效会撤销通过结果，恢复后需重新累计。

实现中先使用单拍延迟输出的历史计数进行限幅和门限比较，再将“限幅计数加 1”送回延迟输入；条件的反值接入 Delay 的 `Level` 复位端。算法并非先给本拍输入加 1，再立即比较新计数。这里按计数达到门限说明确认条件，不将配置值直接换算为首次通过的精确执行拍或秒数。

门限先转换为 `uint32`；当前保存值均为非负整数。门限为 0 时，限幅计数恒为 0，`0>=0` 使检查通过，即使该组有效条件为假也不阻止通过。该配置只免除相应导航数据组的检查，不会清除独立的设备冗余丧失标志。

#### 3.4.2 本机限制派遣原因与就绪状态

本机先将导航检查和设备、操纵状态组合为一个限制派遣原因码。多个条件同时成立时，按下表自上而下取首个满足项；全部不满足时输出 0。因此，输出是有优先顺序的单个原因码，不是所有故障位的集合。

**表 69 本机限制派遣原因的判定顺序**

| 优先顺序 | 成立条件 | 输出代码 |
|---:|---|---:|
| 1 | ADAHRU 冗余丧失、FTADC 冗余丧失，或导航综合检查未通过 | 1 |
| 2 | RA 冗余丧失，或无线电高度检查未通过 | 2 |
| 3 | 任一升力 MCU 的故障反馈无效或故障代码为 3，或升力 MCU 冗余丧失 | 3 |
| 4 | `PilotInSelect≠1`，且（`PilotIn.TEST_IN.Enable_PLTLost_b` 为真或 VDT 冗余丧失） | 4 |
| 5 | `CurrentFccReady=false`，或 FCC 冗余丧失 | 5 |
| 6 | SCU 冗余丧失 | 6 |
| 7 | `PilotInSelect≠2`，且（`RC.TEST_IN.Enable_PLTLost_b` 为真或 GCS 冗余丧失） | 7 |
| 8 | 推力设备冗余丧失 | 8 |
| 默认 | 上述条件均不满足 | 0 |

上述冗余丧失标志由第 2.3.1 节的配置掩码检查形成；两项操纵输入条件中的配置比较与整个括号内条件相与。例如代码 4 要求 `PilotInSelect≠1 AND (操纵输入失联 OR VDT 冗余丧失)`。升力 MCU 条件另检查每台设备的 `FaultLevel.valid/data`，不以功率或转速反馈的有效性代替。

限制派遣原因码为 0 后，还需满足最终选定操纵输入 `Cockpit_In` 未失联、未请求地面站停车，以及预检数据有效且代码为 2，才能形成本机就绪：

```text
本机就绪 = (本机限制派遣原因码 == 0)
           AND NOT Cockpit_In.TEST_IN.Enable_PLTLost_b
           AND NOT Cockpit_In.TEST_IN.Request_Stop_GNDStation_b
           AND MPIOData.PreflightCheckValid.valid
           AND (MPIOData.PreflightCheckValid.data == 2)
```

限制派遣原因码和本机就绪分别写入 `SpCcdlOut.Data.LimitDispathInfo`、`SpCcdlOut.Data.SysReady`。其中 `LimitDispathInfo` 保留模型字段的原拼写。没有限制派遣原因仍可能因最终选定操纵输入或预检条件不满足而未就绪；两项输出不能相互替代。

#### 3.4.3 多机已报告状态的汇总

汇总输入来自 `SysInfoData.CurrentSysReady/LeftSysReady/RightSysReady` 及对应的 `LimitDispatchInfo`。这些字段在前级分别经过消息有效性处理：消息无效时就绪状态为假，限制派遣信息替换为代码 5，见第 2.1.2 节。本级使用这些已处理记录，不直接回接本拍刚写入 `SpCcdlOut` 的结果。

配置参数 `SpCPT.Check_RmsSysReady` 同时影响就绪汇总和限制派遣信息的读取范围，当前保存值为 `uint32(10)`。

```text
如果 Check_RmsSysReady == 0：
    汇总就绪 = CurrentSysReady
    汇总限制派遣信息 = CurrentLimitDispatchInfo
否则：
    对 Current、Left、Right 的就绪状态分别执行连续确认
    汇总就绪 = 三路确认结果全部为真

    按 Current、Left、Right 的顺序，取第一个非零的限制派遣代码
    三路代码均为零时，汇总限制派遣信息为零
```

三路就绪确认共用相同门限，但各自保存计数，使用第 3.4.1 节所述的延迟、复位和比较结构。任一路已报告状态失效都会使正门限下的汇总就绪为假。限制派遣信息则直接按当前代码选择，不等待上述计数，也不比较代码数值大小；Current 为 7、Left 为 1 时，汇总结果仍取 Current 的 7。

独立的 `SysReady` 输出随后进入 SYS 控制律接口的 `SysReady_SYSINFO_b`，并供显示模块使用；`SpCcdlOut.Data.SysReady` 保留本机条件生成的结果。文档据此区分“本机是否满足就绪条件”与“多机报告是否按配置满足汇总条件”，不将两个同名状态写成同一条直接传递链。

### 3.5 SYS 设备状态输出

`Calc_SYSMsg_ToClaw` 将前级设备与 MPIO 处理结果组织为控制律 SYS 接口。它接收 `DevData` 中的 MCU／SCU 记录、`MpioData` 中的高压状态和可用功率，以及 CCDL 模块形成的独立汇总就绪。各字段采用不同的处理规则：高压状态形成使用资格，可用功率按有效性更新，电机反馈按字段直接提取或替代，执行器位置经过标定后输出。最后将这些结果连同汇总就绪装入 `BUS_SYSINFO_IN`。

#### 3.5.1 高压状态与可用功率

消息有效还不足以使高压状态输出为可用。SYS 输出层同时检查高压状态记录的有效标志和状态编码：仅当 `HiVltgSts.valid=true` 且 `HiVltgSts.data<=2` 时，`VCU_Status.VCU_Valid=true`；其他情况为 `false`。该处理依据当前输入直接判定，不累计异常或恢复计数。

同一结构中的可用功率使用自身记录的有效标志决定更新或保持。记录有效时，输出接收本拍 `data`；记录无效时，保持上一拍本级输出。本拍输出同时写回数值历史；该层直接使用前级形成的有效标志，不再执行异常确认或恢复计数。

#### 3.5.3 执行器位置反馈标定

前级 SCU 处理将位置反馈及其有效标志封装为 `Position` 记录；输出层再根据对应舵面的标定参数，形成控制律接口中的舵面角度 `Surface_deg`。位置换算与故障状态采用独立路径：故障状态取前级已经形成的 `ClawFaultStatus.data`，位置换算不重新生成故障等级。

标定使用三个参数：偏置 `P_BIAS` 表示换算时从位置输入中扣除的基准，增益 `P_GAIN` 为比例换算的除数，方向 `P_DIR` 控制换算结果的正负方向。位置有效且增益满足保护条件时，按下式计算：

```text
舵面角度 = (位置反馈 − P_BIAS) × P_DIR / P_GAIN
```

为避免使用接近零的除数，算法先检查 `abs(P_GAIN)>=single(0.01)`。不满足时输出 `single(0)`；满足时才进入标定计算分支，并依据 `Position.valid` 决定更新或保持：

```text
如果增益保护条件不满足：
    舵面角度 = 0
否则：
    如果位置反馈有效：
        按标定公式计算本拍舵面角度
    否则：
        保持计算分支中保存的上一拍舵面角度
```

计算分支中的数值历史初值为 `single(0)`，保存对象是已经换算的舵面角度。该分支的动作端口设置为 `InitializeStates=reset`：首次进入以及退出后重新进入时，内部历史重新初始化。因此，连续处于正常增益分支且位置失效时可保持末次角度；如果先进入增益保护分支、随后恢复正常增益，重新进入计算分支时不能继续依赖退出前的历史。此时位置有效则接收新角度，位置仍无效则输出初始化值 0。位置记录的 `reset` 未接入此计算，分支重入初始化由动作子系统自身控制。

八路舵面共用上述算法，实际参数分别绑定如下。表中的 Gain、Bias 均来自 `SpCPT`，当前字典保存值分别为 `single(1)`、`single(0)`；方向参数在各调用处固定设置。

**表 73 舵面标定参数绑定**

| 舵面字段 | `P_GAIN` | `P_BIAS` | `P_DIR` |
|---|---|---|---:|
| `AilLO` | `SpCPT.AilLO_Gain` | `SpCPT.AilLO_Bias` | −1 |
| `AilLI` | `SpCPT.AilLI_Gain` | `SpCPT.AilLI_Bias` | −1 |
| `AilRO` | `SpCPT.AilRO_Gain` | `SpCPT.AilRO_Bias` | 1 |
| `AilRI` | `SpCPT.AilRI_Gain` | `SpCPT.AilRI_Bias` | 1 |
| `EleL` | `SpCPT.EleL_Gain` | `SpCPT.EleL_Bias` | −1 |
| `EleR` | `SpCPT.EleR_Gain` | `SpCPT.EleR_Bias` | 1 |
| `RudL` | `SpCPT.RudL_Gain` | `SpCPT.RudL_Bias` | −1 |

### 3.6 FMS 数据输出

`Calc_FMSMsg_ToClaw` 从 `MpioData` 接收重量、重心，以及飞行目标和请求状态，形成 `Claw_FMS_In_Msg:BUS_FMS_IN`。重量和重心按记录有效性决定是否接收；其余目标值、业务有效编码和请求状态直接使用记录的 `data`，再按输出类型传递或转换。理解这一差别，才能判断前级记录无效时最终输出如何变化。

#### 3.6.1 重量与重心的条件更新

前级监测形成的数据记录仍可在输出层继续处理。重量和重心只在本项记录有效时接受新值；输入无效时保留本级上一拍输出，避免无效输入的新数值覆盖已保存结果。此处直接使用已经形成的有效标志，不再执行异常确认或恢复计数。

两项独立保存数值历史，采用相同更新关系：

```text
如果本项输入记录有效：
    本拍输出 = 本拍输入数值
否则：
    本拍输出 = 上一拍本级输出

将本拍输出保存为下一拍的数值历史
```

**表 75 重量与重心的输入、初值与输出**

| 应用 | 更新依据 | 本级历史初值 | 最终数值字段 |
|---|---|---|---|

`Calc_SPDispMsg_Out` 将地面站和飞行员两条操纵支路、最终操纵来源、汇总系统状态及高压开关组成显示消息。显示结果同时保留两条操纵支路的数值和组有效性；最终选中的 `Cockpit_In` 只用于此处的来源状态判定，不使另一支路的显示数值被删除。输入关系承接操纵输出的 `RC、PilotIn、Cockpit_In`，见第 3.2.6 节。

#### 3.7.1 操纵来源状态与两支路显示

来源状态先检查最终操纵消息是否失联。`Cockpit_In.TEST_IN.Enable_PLTLost_b=true` 时，显示 `PilotState=uint8(0)`；否则，将 `Cockpit_In.PilotSource` 转为 `uint8` 输出。这里读取已经选定的来源身份，不重新执行操纵来源选择。

```text
组显示有效性 = uint8(第一轴有效 AND 第二轴有效)
第一轴显示数值 = 第一轴当前数值
第二轴显示数值 = 第二轴当前数值
```

### 3.8 DRMS 数据输出

主模型的 `SP2DRMS` 输出组合向 DRMS 提供最终导航有效性，以及备份激活字段及其有效性。导航有效性直接取 `Claw_Nav_Msg.Valid_Status`，不在此重新检查各导航数值；备份激活字段则在两个输入记录之间按有效性与固定优先级选择。

两个候选分别为第一阶段飞行员表决结果 `PilotInData.GPIO[5]` 和地面站结果 `GcsData.KeyBackupFccAct`。选择优先采用前者；只有前者无效时，才考虑地面站记录。这里不使用最终操纵来源配置来选择候选，也不对两个候选值作表决。

```text
如果 PilotInData.GPIO[5] 有效：
    采用该记录的 data
否则，如果 GcsData.KeyBackupFccAct 有效：
    采用地面站记录的 data
否则：
    采用 false

isBfccActv = 将所选结果转换为 boolean
isBfccActvValid = GPIO[5].valid OR KeyBackupFccAct.valid
```

两路都有效而数值不同时，仍由 `GPIO[5]` 决定输出。有效性中的 OR 表示至少有一路候选有效，不是将两个激活值进行 OR 运算。例如，两路都有效、`GPIO[5].data=0`、地面站 `data=1` 时，输出为 `isBfccActv=false` 且 `isBfccActvValid=true`。两路均无效时，两个输出均为 `false`，不保持此前的激活值。

**表 80 DRMS 输出结构**

| `BUS_SP2DRMS_MSG` 字段 | 来源／规则 |
|---|---|
| `navValid` | 整体复制最终导航 `Valid_Status`，类型为 `BUS_FCS_NAV_Valid_Status` |
| `isBfccActv` | 按上述优先规则选取数据并转为 `boolean` |
| `isBfccActvValid` | 两个候选有效标志相或，类型为 `boolean` |

该结构先以零值总线建立，再对三项全部赋值；没有额外的来源编号或 `reset` 字段。数值回到 `false` 的默认动作来自候选均无效的选择分支，不能只凭总线初值解释。实现定位：`VE25SP` SID441/442 读取导航有效性，SID449/452/451/450 读取飞行员第 5 项 GPIO，SID447/448 读取地面站记录，SID454/455 实现优先选择，SID457 形成有效性，SID459 转换布尔值，SID445/446 装配结果，SID458 输出。结构定义见 `SP_Step_New.sldd/BUS_SP2DRMS_MSG`。

需求来源：[信号处理软件高级需求工作簿](../sp/02_Requirements/specification/documents/信号处理软件高级需求-SP_SW_HLR-20250722.xlsx)。本节记录行为关系，正式差异处置及工程变更需另有依据；本次文档升级不修改模型来对齐需求。
